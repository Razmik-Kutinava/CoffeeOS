# TASK PATCH — кривые задачи (патч / доп.задача / переписать)

**Вход:** `/patch` · on-demand `coffeeos-task-patch.mdc`  
**Не** заменяет SBR / commit-ops / intake. **Не** на обычную новую фичу и не на мелочь.

## Пути

| Что | Путь |
|-----|------|
| ТЗ | `docs/operations/milestones/veha_2/requirements/customer_tasks/TASK-*.md` |
| Живой чек-лист | `docs/operations/session/todo.md` (один файл) |
| Карта UI | `docs/operations/session/COMPONENT_MAP.md` |
| Интеграции | `docs/integrations/INTEGRATIONS.md` |

## Когда

- После Review / приёмки: ответ или поведение **кривое**
- Сценарий в Given/When/Then был, код не тот → **ПАТЧ**
- Сценария не было / вернули осознанно убранное → **ДОП.ЗАДАЧА**
- 3+ патча на один TASK подряд → **ПЕРЕПИСАТЬ** документ

## Шаг 1 — сверка с картой

Компонент в карте, запись свежая, «Общий файл с» пусто → аудит не нужен.  
Иначе (нет в карте / общий файл / решаете по памяти) → аудит обязателен.

## Шаг 2 — аудит (только если нужен)

**АУДИТ (БЕЗ ИЗМЕНЕНИЙ КОДА)** — только чтение кода/`git log`; каждый факт = файл:строка.

1. Что делает сейчас по факту  
2. Связь с другими файлами / общим стейтом  
3. `git log`/`blame`: кто менял, привязка к задаче, осознанное удаление (reopen/remove/QA/revert)  
4. Если осознанное удаление — есть ли тест на **отсутствие** функциональности?  
5. Сверить с «Не трогать» в `COMPONENT_MAP.md`  

Формат: `Пункт → Факт → Файл:строка`

## Шаг 3 — классификация

1. Сценарий был в Gherkin, код не соответствует → **ПАТЧ**  
2. Сценарий нигде не зафиксирован → **ДОП.ЗАДАЧА**  
3. Осознанно убрали, сейчас возвращаем → **ДОП.ЗАДАЧА** (+ снять/переписать защитный тест)  
4. 3+ патча на один документ → **ПЕРЕПИСАТЬ**

## Шаг 4 — шаблоны

### ПАТЧ (секция в существующем TASK, не новый файл)

```markdown
## Патч [N]: [дата]
Основание: аудит от [дата], факт [файл:строка]
### Расхождение
Subtask [N]: Given/When/Then было […] / по факту [файл:строка] / расхождение […]
### Исправленный сценарий
- [ ] Subtask [N] (patch v[X]): Given/When/Then […]
### Не трогать
См. COMPONENT_MAP.md строка [Компонент]: […]
### Scope
Разрешено: […] / Запрещено: […]
```

### ДОП.ЗАДАЧА (всегда новый файл)

- Расширяет → `TASK-[НАЗВАНИЕ]-EXT.md`, шапка: **Расширяет:** …; **Реверсирует:** … (если есть)  
- Самостоятельная → `TASK-[НАЗВАНИЕ].md`, шапка: **Тип:** новая задача  

```markdown
# TASK: [Название]
[шапка]
Бизнес-цель: […]
## 1. Карта интеграций — затронуто / нет
## 2. Карта компонентов — компонент; общий файл (да/нет+граница); новый (да/нет)
## 3. Текущее поведение (факт) — если применимо
## 4. Scope — разрешено/запрещено (+ защитный тест при реверсе)
## 5. Gherkin
- [ ] Subtask: Given/When/Then ([ОТКРЫТЫЙ ВОПРОС] если надо)
## 6. TDD-проверка: команды
[открытые вопросы → документ не готов к билду]
```

### ПЕРЕПИСАТЬ

Старое не удалять: `## УСТАРЕЛО, см. ниже` → новая версия следом в том же файле.

## Шаг 5 — `todo.md`

Вставить/заменить секцию (не новый `todo-*.md`):

```markdown
## SBR: [фаза]
## Файлы (ожидаемо): […]
## Не ломать: […] (ссылка на COMPONENT_MAP при общем файле)
## Проверка: [команды]
## DoD: […]
```

## Шаг 6 — `COMPONENT_MAP.md` (только после Review, тесты зелёные)

Правило **один файл = одна строка**:

1. Для каждого файла из БЛОК 4: строка есть → точечно PR + «Не трогать»; **не** менять «Назначение» на имя задачи; **не** сливать файлы в одну ячейку. Нет строки → добавить с описанием файла.  
2. Закрытые «требует аудита» → факт / ссылка на задачу.  
3. Закрытые «Известные дыры» → удалить пункт.  
4. Остальное не трогать. Docs-only. Коммит: `docs: update COMPONENT_MAP — [компоненты]`.  
5. Самопроверка: путь в колонке «Файл» не дублируется.

## Жёсткие правила

1. Патч = секция в старом файле. Доп.задача = всегда новый файл.  
2. Общий файл → граница одинаково в Scope и в `COMPONENT_MAP`.  
3. Один живой `todo.md`.  
4. Реверс = доп.задача + проверка защитных тестов.  
5. Карта меняется только после Review, не на Spec.
