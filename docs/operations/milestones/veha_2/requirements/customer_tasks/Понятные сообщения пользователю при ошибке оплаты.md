# Понятные сообщения пользователю при ошибке оплаты

## Текст заказчика (дословно)

Задача: Понятные сообщения пользователю при ошибке оплаты

Бизнес-цель: дополнить существующий сценарий ошибки One-Click понятными пользовательскими сообщениями, чтобы пользователь понимал причину неуспешной оплаты и знал, что делать дальше.

Задача является дополнительной UX-доработкой к существующему сценарию обработки ошибки оплаты.

1. Контекст и проблема

При попытке оплаты пользователь может получить ошибку, но текущего сообщения недостаточно, чтобы понять:

- почему платеж не прошел;
- связана ли проблема с картой или с соединением;
- нужно ли менять карту;
- нужно ли просто повторить оплату.

Необходимо добавить понятные поясняющие сообщения непосредственно в существующий сценарий ошибки оплаты.

2. Сценарии и пользовательские сообщения

Сценарий 1: Ошибка связана с картой

Если оплата не прошла по причине, связанной с картой, пользователю показать текст:

«Недостаточно средств, или карта заблокирована банком, или истёк срок действия карты»

Сообщение должно объяснять возможные причины отказа без необходимости пользователю самостоятельно разбираться в техническом статусе платежа.

После сообщения пользователь должен понимать, что следующим действием может быть:

- выбор другой привязанной карты;
- добавление новой карты;
- повторная попытка оплаты.

Сценарий 2: Нет связи / временная ошибка соединения

Если платеж не был выполнен из-за отсутствия связи или временной сетевой ошибки, показать пользователю текст:

«Нет связи. Повторить»

"«Повторить»" должно быть понятным действием, позволяющим повторить попытку оплаты после восстановления соединения.

Повторная попытка должна использовать существующую логику оплаты и не создавать новый отдельный payment flow.

3. UX-требования

- Сообщение должно быть понятным обычному пользователю и не содержать технических кодов ошибок эквайринга.
- Сообщение должно отображаться в контексте ошибки оплаты.
- Для ошибки карты пользователь должен понимать возможные причины и дальнейшее действие.
- Для ошибки соединения пользователь должен видеть явное действие «Повторить».
- Не дублировать одно и то же сообщение в нескольких местах одновременно.
- Сообщения не должны перекрывать или ломать существующий layout.
- Добавление текстов не должно изменять существующее поведение успешной оплаты.
- Добавление сообщений не должно изменять бизнес-логику эквайринга.

4. Ограничения

Разрешено менять

- текстовые сообщения состояния ошибки оплаты;
- UI-компонент отображения ошибки;
- отображение CTA "Повторить" для сетевой ошибки;
- UI-связь сообщения с существующим сценарием повторной оплаты.

Запрещено менять

- API эквайринга;
- payment request и payload;
- бизнес-логику One-Click;
- обработку платежа;
- структуру БД;
- существующий успешный сценарий оплаты;
- интеграционный контракт эквайринга.

Если существующая система уже предоставляет тип/статус ошибки, использовать его для выбора соответствующего сообщения. Не добавлять новую бизнес-логику определения причины платежного отказа без необходимости.

5. Критерии приёмки

- [ ] При ошибке, связанной с картой, пользователь видит текст: «Недостаточно средств, или карта заблокирована банком, или истёк срок действия карты».
- [ ] При отсутствии связи/сетевой ошибке пользователь видит текст: «Нет связи. Повторить».
- [ ] Для сетевой ошибки действие "Повторить" доступно пользователю.
- [ ] Нажатие "Повторить" запускает существующий сценарий повторной оплаты.
- [ ] Сообщения не содержат технических кодов или внутренних статусов эквайринга.
- [ ] Сообщения не дублируются внутри шторки выбора способа оплаты.
- [ ] Существующий сценарий успешной оплаты не изменился.
- [ ] Бизнес-логика эквайринга и API-контракты не изменились.
- [ ] Layout экрана заказа и шторки не ломается после добавления сообщений.
