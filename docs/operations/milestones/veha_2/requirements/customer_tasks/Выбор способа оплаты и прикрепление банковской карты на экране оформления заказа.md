# Выбор способа оплаты и прикрепление банковской карты на экране оформления заказа

## Бизнес-контекст
На экране оформления заказа после регистрации пользователя отсутствует функционал выбора способа оплаты. Пользователь не может привязать банковскую карту и завершить покупку. Конверсия в покупку равна нулю без этого функционала. Bottom sheet имеет три состояния: peek, expanded, expanded+. Внутри expanded+ переключаются экраны: список способов оплаты → форма ввода карты → 3D Secure → список способов оплаты.

## Глобальные ограничения
- Не менять логику экрана регистрации и корзины — только добавлять блок оплаты
- Метод СБП отображается в состоянии disabled, обработка платежей через СБП не реализуется
- Максимальное количество сохранённых карт: 10
- Не реализуем повторную отправку СМС-кода по истечении таймера (отдельная задача)
- Три состояния bottom sheet: peek, expanded, expanded+
- В peek состоянии все три кнопки (СБП, Картой +, Оплатить) неактивны до подтверждения email
- Кнопка "Оплатить" активна только если прикреплена хотя бы одна карта
- На форме карты и экране 3D Secure наверху отображается цена заказа и неактивная кнопка с ценой
- При регистрации шторка всегда в состоянии peek

## Сценарии реализации (Use Cases в Gherkin)

### Шаг 1: Регистрация → Peek состояние

- [ ] 
  - Given: Пользователь находится на экране регистрации (поля: Имя, Email, Отправить код, Код из письма, Подтвердить email), bottom sheet в состоянии peek
  - When: В корзине 3 товара
  - Then: Bottom sheet показывает 3 миниатюры товаров с горизонтальным скроллом, каждая миниатюра имеет счётчик (- 1 +). Внизу три кнопки: СБП (disabled), Картой + (disabled), Оплатить (disabled). Положение peek настроено так, чтобы не мешать форме регистрации

- [ ] 
  - Given: Пользователь находится на экране регистрации, bottom sheet в состоянии peek
  - When: В корзине 1 товар
  - Then: Bottom sheet показывает полную карточку товара с изображением, названием ("Фильтр-кофе без кофеина (декаф) Гватемала"), ценой и объёмом (3Р × 1), описанием ("Со льдом", "Кардамон и корица — пряный акцент, без сладости"), счётчиком (- 1 +), кнопкой "Удалить". Внизу три кнопки: СБП (disabled), Картой + (disabled), Оплатить (disabled)

- [ ] 
  - Given: Пользователь находится на экране регистрации, bottom sheet в состоянии peek
  - When: В корзине более 3 товаров
  - Then: Bottom sheet показывает 3 миниатюры товаров, доступен горизонтальный скролл для просмотра остальных товаров. Внизу три кнопки: СБП (disabled), Картой + (disabled), Оплатить (disabled)

- [ ] 
  - Given: Пользователь ввёл код из письма в поле "Код из письма"
  - When: Пользователь нажимает "Подтвердить email" и получает успешный ответ сервера
  - Then: Кнопки СБП остаётся disabled, Картой + становится активной, Оплатить становится активной только если прикреплена хотя бы одна карта (иначе disabled). Bottom sheet остаётся в peek состоянии

### Шаг 2: Peek → Expanded состояние

- [ ] 
  - Given: Bottom sheet в состоянии peek, email подтверждён
  - When: Пользователь скроллит шторку наверх
  - Then: Панель раскрывается в expanded-состояние за ≤ 400 мс, показывает все товары корзины. Если товаров > 3, доступен горизонтальный скролл. Отображаются методы оплаты: "Картой *XXXX" (если есть сохранённые карты), "СБП" (disabled), "Картой +". Кнопка "Оплатить" активна только если прикреплена хотя бы одна карта

- [ ] 
  - Given: Bottom sheet в состоянии expanded, сохранённых карт нет
  - When: Пользователь видит кнопку "Оплатить"
  - Then: Кнопка "Оплатить" в состоянии disabled

- [ ] 
  - Given: Bottom sheet в состоянии expanded, прикреплена хотя бы одна карта
  - When: Пользователь видит кнопку "Оплатить"
  - Then: Кнопка "Оплатить" активна

### Шаг 3: Expanded → Expanded+ состояние

- [ ] 
  - Given: Bottom sheet в состоянии expanded
  - When: Пользователь нажимает на блок "Способ оплаты"
  - Then: Панель переходит в expanded+ состояние за ≤ 400 мс, карточки товаров сворачиваются в миниатюры (2 карточки видны сверху), основное пространство занимает блок "Способ оплаты" со списком сохранённых карт ("Картой *1594" — может быть несколько штук), "СБП" (disabled), "Картой +", кнопка "Оплатить", кнопка закрытия (X) в правом верхнем углу

- [ ] 
  - Given: Bottom sheet в состоянии expanded+, прикреплена хотя бы одна карта
  - When: Пользователь видит кнопку "Оплатить"
  - Then: Кнопка "Оплатить" активна

- [ ] 
  - Given: Bottom sheet в состоянии expanded+, сохранённых карт нет
  - When: Пользователь видит кнопку "Оплатить"
  - Then: Кнопка "Оплатить" в состоянии disabled

### Шаг 4: Добавление карты (форма ввода внутри expanded+)

- [ ] 
  - Given: Bottom sheet в состоянии expanded+, отображается список способов оплаты
  - When: Пользователь нажимает "Картой +"
  - Then: Внутри expanded+ открывается форма ввода карты, наверху отображается цена заказа и неактивная кнопка с ценой, поля: "Номер карты" (16 цифр), "ММ / ГГ" (4 цифры), "CMC/CVV" (3 цифры), свитч "Использовать карту для будущих заказов" (включён по умолчанию, текст: "Это безопасно, данные зашифрованы"), кнопка "Далее"

- [ ] 
  - Given: Форма ввода карты открыта, все поля заполнены корректно
  - When: Пользователь нажимает "Далее"
  - Then: Внутри expanded+ открывается экран 3D Secure

- [ ] 
  - Given: Форма ввода карты открыта, пользователь не заполнил форму
  - When: Пользователь закрывает форму
  - Then: Возврат к списку способов оплаты внутри expanded+

### Шаг 5: 3D Secure

- [ ] 
  - Given: Экран 3D Secure открыт внутри expanded+
  - When: Пользователь видит экран
  - Then: Наверху отображается цена заказа и неактивная кнопка с ценой, поле "СМС код", таймер обратного отсчёта (00:59), цифровая клавиатура (1-9, *, 0, ., >), кнопка "Разрешить". Вызов цифровой клавиатуры (не системной)

- [ ] 
  - Given: Экран 3D Secure открыт, таймер показывает 00:59
  - When: Пользователь нажимает кнопки цифровой клавиатуры
  - Then: Цифры вводятся в поле "СМС код", кнопка ">" удаляет последний символ (backspace)

- [ ] 
  - Given: Пользователь ввёл корректный СМС-код, свитч "Использовать карту для будущих заказов" включён
  - When: Пользователь нажимает "Разрешить"
  - Then: Карта сохраняется в профиль пользователя, внутри expanded+ возвращается список способов оплаты, новая карта отображается как "Картой *1594", кнопка "Оплатить" становится активной

- [ ] 
  - Given: Пользователь ввёл корректный СМС-код, свитч "Использовать карту для будущих заказов" выключен
  - When: Пользователь нажимает "Разрешить"
  - Then: Карта не сохраняется в профиль, оплата проходит без сохранения

### Шаг 6: Оплата

- [ ] 
  - Given: Bottom sheet в состоянии expanded+, прикреплена хотя бы одна карта, кнопка "Оплатить" активна
  - When: Пользователь выбирает метод оплаты (карту) и нажимает "Оплатить"
  - Then: Переход к подтверждению заказа

### Шаг 7: Навигация и закрытие

- [ ] 
  - Given: Bottom sheet в состоянии expanded+
  - When: Пользователь нажимает кнопку закрытия (X) в правом верхнем углу
  - Then: Возврат в expanded состояние за ≤ 400 мс, карточки товаров разворачиваются

- [ ] 
  - Given: Bottom sheet в состоянии expanded или expanded+, товаров > 3
  - When: Пользователь выполняет горизонтальный скролл (более 3х прокруток)
  - Then: Пользователь листает товары влево/вправо, скролл работает плавно

- [ ] 
  - Given: Bottom sheet в состоянии expanded или expanded+
  - When: Пользователь выполняет скролл вниз и нажимает на карточку товара
  - Then: Открывается карточка товара (pop-up внутри карточки) в течение 200 мс

## Экстремальные сценарии (Error & Edge States)

- [ ] Таймер 3D Secure истекает (00:00) → кнопка "Разрешить" блокируется, пользователь должен начать процесс добавления карты заново
- [ ] Пользователь вводит неверный СМС-код → показывается сообщение об ошибке, поле "СМС код" очищается, таймер продолжает отсчёт
- [ ] Сеть пропадает во время 3D Secure → показывается сообщение об ошибке соединения, пользователь может повторить попытку
- [ ] Пользователь нажимает "Картой +", но не заполняет форму и закрывает её → возврат к списку способов оплаты внутри expanded+, данные формы не сохраняются
- [ ] Пользователь пытается добавить 11-ю карту → показывается сообщение о достижении лимита (10 карт), форма не открывается
- [ ] Сеть пропадает при подтверждении email → кнопки остаются в состоянии disabled (СБП, Картой +, Оплатить), показывается сообщение об ошибке, пользователь может повторить подтверждение
- [ ] Пользователь удаляет все сохранённые карты в expanded+ → кнопка "Оплатить" переходит в состояние disabled
- [ ] Форма ввода карты содержит невалидные данные (неверный номер карты, истёкший срок действия, неверный CVV) → кнопка "Далее" остаётся disabled, показывается валидация полей
- [ ] Пользователь находится в состоянии peek до подтверждения email и пытается взаимодействовать с кнопками → все три кнопки (СБП, Картой +, Оплатить) не реагируют на нажатия (disabled)
- [ ] В корзине 0 товаров → bottom sheet не отображается или показывает пустое состояние

## Критерии авто-выхода (Exit Criteria)
1. Код проходит unit/интеграционные тесты под все сценарии из раздела "Сценарии реализации" и "Экстремальные сценарии".
2. Проверка типов TypeScript (tsc) и линтер проходят без ошибок сборки.
3. Bottom sheet корректно переключается между тремя состояниями (peek, expanded, expanded+) с анимацией ≤ 400 мс.
4. В peek состоянии при 1 товаре показывается полная карточка товара, при 3 товарах — горизонтальный скролл миниатюр со счётчиками.
5. Кнопка "Оплатить" активна только при наличии хотя бы одной сохранённой карты.
6. Кнопки СБП, Картой +, Оплатить в peek состоянии неактивны до подтверждения email.
7. Форма ввода карты и экран 3D Secure отображаются внутри expanded+ без выхода за пределы bottom sheet.
8. Цифровая клавиатура 3D Secure корректно вводит символы и удаляет последний символ кнопкой ">".
9. Таймер 3D Secure отображает обратный отсчёт от 00:59 и блокирует кнопку "Разрешить" при достижении 00:00.
10. Горизонтальный скролл товаров работает плавно при количестве товаров > 3.
11. Цена заказа отображается на форме карты и экране 3D Secure.
12. Метод СБП отображается в состоянии disabled во всех состояниях bottom sheet.
13. Свитч "Использовать карту для будущих заказов" включён по умолчанию с текстом "Это безопасно, данные зашифрованы".
14. При скролле вниз и нажатии на карточку товара открывается pop-up карточки товара.
