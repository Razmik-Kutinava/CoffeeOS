## Текст заказчика (дословно)

### Задачи

Заменить элемент «Витрина» в правом верхнем углу шапки на «Профиль › ID» и убрать раздел «Профиль» из нижней навигации в связи с переходом на новую навигацию

### Проблема

В приложении CoffeeOS планируется переход на новую нижнюю навигацию, в которой раздел «Профиль» будет исключён из нижнего бара. При этом текущий элемент «Витрина» в правом верхнем углу шапки (рядом с логотипом «CoffeeOS») не несёт навигационной ценности и занимает место, где логичнее разместить быстрый доступ к профилю пользователя.
Без переноса профиля в шапку пользователь потеряет точку входа в свой аккаунт после замены нижнего бара.

### Решение

**Продуктовые требования:**

- Пользователь получает точку входа в профиль из шапки приложения — это единственное место, откуда можно перейти в профиль после замены нижней навигации.
- Отображение ID пользователя рядом со словом «Профиль» позволяет сразу идентифицировать аккаунт (например, для обращения в поддержку или проверки бонусного счёта) без дополнительных переходов.
- Элемент «Витрина» удаляется из шапки, так как его функция дублируется содержимым главной страницы.

**Технологические требования:**

- Изменения вносятся в компонент шапки (Header) и компонент нижней навигации (BottomTabBar).
- ID пользователя подтягивается из текущего контекста авторизации. Если пользователь не авторизован — отображается только текст «Профиль» без ID.
- Верстка должна корректно отображаться на экранах от 320 px шириной.

### User story

Как пользователь приложения CoffeeOS, я хочу видеть свой профиль и ID в правом верхнем углу шапки вместо надписи «Витрина», чтобы иметь доступ к аккаунту после замены нижней навигации и сразу видеть свой идентификатор.

### Use case

1. Пользователь открывает главную страницу приложения.
2. В левом верхнем углу шапки отображается логотип «CoffeeOS».
3. В правом верхнем углу шапки (на месте, где ранее была надпись «Витрина») отображается элемент «Профиль › [ID]» (например, «Профиль › 100234»).
4. В нижней навигации раздел «Профиль» отсутствует (в соответствии с новой навигацией).
5. Пользователь нажимает на «Профиль › [ID]» в шапке.
6. Открывается экран профиля с информацией об аккаунте.

### Corner cases

- Если ID пользователя длиннее 8 символов — отображается сокращённый формат (например, «1002…34»). Полный ID доступен на экране профиля.
- Если пользователь не авторизован — в шапке отображается только текст «Профиль» без ID. При нажатии открывается экран авторизации.
- На экранах с шириной менее 360 px текст «Профиль › ID» может сокращаться до иконки пользователя с числовым бейджем ID.

### Ограничения, чего не делаем

- Не меняем функциональность экрана профиля — только точку входа и отображение в шапке.
- Не меняем логику авторизации и получения ID.
- Не удаляем раздел «Профиль» из системы — только меняем его расположение.
- Не меняем содержимое и логику работы нижней навигации за пределами удаления раздела «Профиль» (замена нижнего бара — отдельная задача).

### Критерии приёмки

| № | Измеритель | Целевой показатель | Критерий успеха |
|---|------------|-------------------|-----------------|
| 1 | Наличие элемента «Профиль › ID» в правом верхнем углу шапки на главной странице (на месте элемента «Витрина») | Элемент «Витрина» отсутствует, элемент «Профиль › ID» присутствует, ID отображается корректно | Допустимо: ID отображается в сокращённом формате при длине > 8 символов |
| 2 | Отсутствие раздела «Профиль» в нижней навигации | В нижней навигации нет раздела «Профиль» | Раздел «Профиль» полностью удалён из BottomTabBar |
| 3 | Переход в профиль по нажатию на элемент в шапке | Открывается экран профиля | Время отклика ≤ 300 мс |
| 4 | Отображение для неавторизованного пользователя | Отображается только «Профиль» без ID | При нажатии открывается экран авторизации |
| 5 | Корректность вёрстки на экранах 320–428 px | Элемент не выходит за границы шапки, не перекрывает логотип «CoffeeOS» | Допустимо: на экранах < 360 px используется иконка вместо текста |

## Текст заказчика (дословно, rev2 №4)

### Задача

Реализовать управление количеством товаров и удаление позиций в поп-апе корзины

### Проблема

Пользователь не может управлять количеством товаров и удалять позиции из корзины без перехода на отдельный экран корзины. Текущий процесс требует 3 дополнительных перехода (каталог → корзина → изменение количества → каталог), что увеличивает время оформления заказа на 40-60 секунд и создает 4 дополнительных клика на одну операцию изменения количества.

### Решение

**Продуктовые требования:**

- В режиме expanded пользователь удаляет позиции текстовой кнопкой «Удалить».
- В режимах peek и expanded пользователь изменяет количество товара кнопками «+» и «-».
- Кнопка «-» заблокирована (disabled state), когда количество товара равно 1.
- Кнопка «+цена» отображает итоговую сумму и ведет на экран оформления заказа.
- При изменении количества общая сумма пересчитывается в течение 100ms.

**Технологические требования:**

- Кнопки «+» и «-» изменяют количество товара на 1 единицу.
- Текстовая кнопка «Удалить» доступна только в режиме expanded (в режиме peek кнопка скрыта).
- Минимальное количество товара: 1 единица. При достижении 1 единицы кнопка «-» переходит в состояние disabled.
- Максимальное количество товара: 99 единиц. При достижении 99 единиц кнопка «+» переходит в состояние disabled.
- Пересчёт суммы выполняется синхронно при изменении количества.

### User Story

Как покупатель приложения CoffeeOS, я хочу управлять количеством товаров и удалять позиции прямо в поп-апе корзины, чтобы быстро корректировать заказ без перехода на отдельный экран корзины.

### Use Case

1. Пользователь видит поп-ап корзины в режиме expanded.
2. Пользователь нажимает кнопку «+» у товара.
3. Система увеличивает количество товара на 1.
4. Система пересчитывает общую сумму заказа в течение 100ms.
5. Пользователь нажимает кнопку «-» у товара.
6. Система уменьшает количество товара на 1.
7. Система пересчитывает общую сумму заказа в течение 100ms.
8. Пользователь нажимает текстовую кнопку «Удалить».
9. Система удаляет позицию из корзины.
10. Система пересчитывает общую сумму заказа в течение 100ms.
11. Если корзина пуста, поп-ап закрывается в течение 300ms.
12. Пользователь нажимает кнопку «+цена».
13. Система переходит на экран оформления заказа.

### Corner Cases

- При количестве 1 кнопка «-» заблокирована (disabled state), удаление позиции выполняется только через текстовую кнопку «Удалить».
- При количестве 99 кнопка «+» заблокирована (disabled state).
- В режиме peek текстовая кнопка «Удалить» скрыта, доступны только кнопки «+» и «-» (при этом «-» заблокирована, если количество равно 1).

### Ограничения

- Не меняем логику расчета цены товаров.
- Не меняем структуру данных корзины.

### Критерии приёмки

| Измеритель | Целевой показатель | Критерий успеха |
|------------|-------------------|-----------------|
| Увеличение количества | Кнопка «+» увеличивает количество товара на 1 единицу | 100% нажатий, отклонение 0% |
| Уменьшение количества | Кнопка «-» уменьшает количество товара на 1 единицу | 100% нажатий, отклонение 0% |
| Блокировка кнопки «-» | Кнопка «-» переходит в состояние disabled при количестве 1 | 100% случаев достижения лимита |
| Удаление позиции | Текстовая кнопка «Удалить» удаляет позицию из корзины | 100% нажатий, отклонение 0% |
| Пересчёт суммы | Общая сумма пересчитывается после изменения количества | Время пересчёта ≤ 100ms, отклонение ±20ms |
| Доступность кнопок в peek | В режиме peek доступны только кнопки «+» и «-», текстовая кнопка «Удалить» скрыта | 100% случаев отображения peek режима |
| Переход к оформлению | Кнопка «+цена» ведет на экран оформления заказа | 100% нажатий, отклонение 0% |
| Закрытие поп-апа при пустой корзине | При удалении последней позиции поп-ап закрывается | Время закрытия ≤ 300ms, отклонение ±50ms |

### Задача

Реализовать поп-ап корзины с тремя состояниями, заменить навигацию нижнего бара и адаптировать поп-ап под скролл каталога

### Проблема

Отсутствует визуальный компонент поп-апа корзины на экране каталога CoffeeOS. Пользователь не видит добавленные товары без перехода на отдельный экран корзины через нижний бар навигации (Каталог → Корзина → Избранное → Профиль), что увеличивает количество шагов до оформления заказа и снижает конверсию.
Текущая навигация нижнего бара содержит отдельную вкладку «Корзина», которая требует от пользователя полного перехода с экрана каталога на экран корзины, теряя контекст просмотра товаров. Это создаёт трение в пользовательском пути: чтобы добавить ещё один товар после просмотра корзины, пользователь вынужден возвращаться назад в каталог.
Поп-ап корзины в развёрнутом состоянии перекрывает контент каталога при прокрутке, что мешает пользователю просматривать товары. Отсутствует автоматическая адаптация размера поп-апа в зависимости от действий пользователя со скроллом.

### Решение

**Продуктовые требования:**

- Заменить текущую навигацию нижнего бара (Каталог, Корзина, Избранное, Профиль) на новую схему с тремя вкладками: Каталог, Избранное, Профиль
- Вкладка «Корзина» удаляется из нижнего бара, её функцию выполняет поп-ап корзины
- Создать поп-ап корзины в нижней части экрана с тремя состояниями: expanded, peek, hidden (чип)
- В режиме expanded отображать полный список товаров с карточками
- В режиме peek отображать сокращённый вид с основными элементами управления
- В режиме hidden отображать чип с общей суммой заказа
- Поп-ап корзины отображается поверх экрана каталога и не требует перехода на отдельный экран
- Поп-ап автоматически адаптируется под скролл главного экрана каталога
- При скролле вниз поп-ап переходит из expanded в peek, затем в hidden (чип)
- При свайпе вверх на поп-апе система раскрывает поп-ап обратно в expanded
- Пользователь всегда видит минимальную информацию о корзине (чип с суммой)

**Технологические требования:**

- Поп-ап должен быть закреплён в нижней части экрана, выше области нижнего бара
- Реализовать плавные анимации перехода между состояниями
- Компонент должен быть адаптирован под разные размеры экранов
- Удалить вкладку «Корзина» из компонента нижнего бара навигации
- Нижняя навигация должна содержать 3 вкладки: Каталог, Избранное, Профиль
- Отслеживать направление и величину скролла главного экрана
- Реализовать пороговые значения для переключения между состояниями
- Сохранять состояние поп-апа при навигации между экранами

### User Story

Как покупатель приложения CoffeeOS, я хочу видеть поп-ап корзины в нижней части экрана каталога и не переходить на отдельный экран корзины через нижний бар, чтобы быстро просматривать добавленные товары, общую сумму заказа и не терять контекст каталога.
Как покупатель приложения CoffeeOS, я хочу, чтобы поп-ап корзины автоматически сворачивался при прокрутке каталога, чтобы не мешал просмотру товаров, но оставался видимым в виде чипа.

### Use Case

1. Пользователь находится на экране каталога
2. Нижняя навигация отображает 3 вкладки: Каталог, Избранное (вкладка «Корзина» отсутствует)
3. Пользователь добавляет товар в корзину из карточки товара
4. Система переносит пользователя на главный экран каталога
5. Система отображает поп-ап корзины в режиме expanded в нижней части экрана, выше нижнего бара
6. В поп-апе отображаются карточки добавленных товаров с изображением, названием, ценой × количеством и выбранными модификаторами
7. Поп-ап закреплён в нижней части экрана
8. Пользователь может переключаться между вкладками нижнего бара (Каталог, Избранное, Профиль) без потери состояния корзины
9. Пользователь находится на главном экране каталога с открытым поп-апом в режиме expanded
10. Пользователь начинает скроллить каталог вниз
11. Система переводит поп-ап в режим peek
12. Пользователь продолжает скроллить вниз
13. Система переводит поп-ап в режим hidden (чип)
14. Пользователь делает свайп вверх на поп-апе
15. Система раскрывает поп-ап в режим expanded (при более одной карточке товара)
16. При свайпе вниз поп-ап остается видимым

### Corner Cases

- При первом добавлении товара поп-ап автоматически раскрывается в режим expanded
- При отсутствии товаров в корзине поп-ап не отображается, нижний бар остаётся в составе 3 вкладок
- При переходе на вкладку «Избранное» или «Профиль» состояние поп-апа сохраняется
- При возврате на вкладку «Каталог» поп-ап отображается в том состоянии, в котором был оставлен
- При одном товаре в корзине свайп вверх не раскрывает поп-ап
- При скролле вверх поп-ап не раскрывается автоматически (только по свайпу на поп-апе)
- При переходе на другой экран и возврате поп-ап сохраняет свое состояние

### Ограничения

- Не меняем структуру категорий и карточек товаров в каталоге
- Не меняем содержимое и логику вкладок «Избранное» и «Профиль»
- Не меняем иконки и подписи оставшихся вкладок нижнего бара
- Не меняем логику скролла самого каталога
- Не меняем структуру категорий

### Задача

Реализовать управление товарами в поп-апе корзины

### Проблема

Пользователь не может управлять количеством товаров и удалять позиции из корзины без перехода на отдельный экран корзины. Это увеличивает время оформления заказа и создает лишние клики.

### Решение

**Продуктовые требования:**

- В режиме expanded пользователь может удалять позиции кнопкой "Удалить"

- Кнопки "+" и "-" изменяют количество товара на 1
- При количестве 0 позиция автоматически удаляется из корзины

5. Пользователь нажимает кнопку "-" у товара

10. Система пересчитывает общую сумму заказа
11. Если корзина пуста, поп-ап закрывается
12. Пользователь нажимает кнопку "+цена"
13. Система переходит на экран оформления заказа

- При количестве 1 кнопка "-" доступна, но при нажатии позиция удаляется
- При максимальном количестве товара (ограничение склада) кнопка "+" блокируется
- В режиме peek кнопка "Удалить" недоступна (доступна только в expanded)

### Ограничения

- Не меняем логику расчета цены товаров
- Не меняем структуру данных корзины

## Текст заказчика (дословно)

### Задача

Реализовать редактирование модификаторов и горизонтальный скролл в поп-апе

### Проблема

Пользователь не может отредактировать выбранные модификаторы товара (температура, вкус, интенсивность) без полного удаления товара и повторного добавления. При большом количестве товаров поп-ап становится слишком высоким и неудобным.

### Решение

**Продуктовые требования:**

- Нажатие ( press) режим expanded, режим peek, режиме hidden на изображение товара открывает карточку товара для редактирования модификаторов
- При более 3х повторениях товара или карточке в поп-апе включается горизонтальный скролл
- Пользователь может быстро изменить в карточке товара модификаторы и вернуться в каталог

**Технологические требования:**

- Реализовать обработку нажатия ( press)
- При активации press открывать карточку товара с уже выбранными модификаторами
- Реализовать горизонтальный скролл для карточек товаров в поп-апе при >3 товаров
- Сохранять выбранные модификаторы при редактировании

### User Story

Как покупатель приложения CoffeeOS, я хочу быстро редактировать модификаторы добавленного товара и видеть все товары в компактном виде при большом количестве позиций.

### Use Case

1. Пользователь видит поп-ап корзины с добавленными товарами
2. Пользователь делает долгое нажатие (нажимает палец 0,5 секунды) на изображение товара
3. Система открывает карточку товара с уже заполненными выбранными модификаторами
4. Пользователь изменяет модификаторы (например, меняет температуру с "Со льдом" на "Горячий")
5. Пользователь нажимает кнопку сохранения
6. Система обновляет товар в корзине с новыми модификаторами
7. Система закрывает карточку товара и возвращает пользователя в каталог
8. При добавлении более 3х одинаковых товаров или разных товаров в поп-апе включается горизонтальный скролл
9. Пользователь может прокручивать товары горизонтально

### Corner Cases

- Если товар не имеет модификаторов, долгое нажатие не активируется или просто открывает карточку
- При горизонтальном скролле индикаторы показывают текущую позицию
- При редактировании модификаторов цена может измениться (если модификатор платный)

### Ограничения

- Не меняем логику выбора модификаторов в карточке товара
- Не меняем структуру данных модификаторов

### Критерии приёмки

| Измеритель | Целевой показатель | Критерий успеха |
|------------|-------------------|-----------------|
| Долгое нажатие | Удержание изображения товара 0,5 секунды открывает карточку товара | 100% случаев |
| Заполнение модификаторов | Карточка товара открывается с уже выбранными модификаторами | 100% случаев |
| Сохранение изменений | После редактирования модификаторы обновляются в корзине | 100% случаев |
| Горизонтальный скролл | При более 3х товарах в поп-апе включается горизонтальный скролл | 100% случаев |
| Индикаторы скролла | При горизонтальном скролле отображаются индикаторы позиции | 100% случаев |
| Обновление цены | При изменении платных модификаторов цена пересчитывается | 100% случаев |
