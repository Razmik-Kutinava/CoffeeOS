## Текст задачи (дословно) — Google Doc Spec

TASK_89-UI-EXT : UI/UX авторизации PWA — экран ввода телефона
Расширяет: docs/operations/milestones/veha_2/requirements/customer_tasks/TASK_89: Авторизация и регистрация PWA — Callcheck → SMS.md
Тип: дополнительная задача — UI/UX
Основание: фактический UI PWA, зафиксированный на скриншотах от 16.09.2026.
Бизнес-цель: во время авторизации по телефону не отвлекать пользователя элементами checkout и не создавать ощущение, что экран оплаты уже доступен до завершения авторизации.
1. Карта интеграций — затронуто / нет
Интеграционная логика Callcheck → SMS не изменяется.
Не затронуто:
SMS.ru;
Callcheck API;
/init_callcheck;
/check_status;
/verify_sms;
регистрация/поиск MobileCustomer;
выдача customer session / refresh token.
Изменяется только отображение checkout во время авторизационного wizard.
2. Карта компонентов
Компоненты авторизации и checkout затронуты.
Общий файл с другими задачами: да, граница обязательна.
Разрешается изменять только поведение UI во время активного phone-auth wizard.
Запрещено изменять:
бизнес-логику Callcheck;
регистрацию пользователя;
SMS fallback;
PaymentMethodsSheet;
состав заказа;
расчёт суммы заказа;
существующую механику checkout вне состояния авторизации.
UX-референсы: при реализации использовать существующий UX Guide проекта и предоставленные скриншоты как визуальный референс.
3. Текущее поведение
По фактическому экрану авторизации:
При вводе телефона пользователь остаётся в checkout.
В нижней части сохраняется CTA с суммой заказа.
Одновременно отображается preview/состав корзины.
Нижняя checkout-sheet занимает значительную часть экрана.
При открытой экранной клавиатуре эти элементы дополнительно конкурируют с полем телефона за вертикальное пространство.
4. Scope
Разрешено
На состоянии phone-auth скрыть CTA с суммой заказа.
На состоянии phone-auth скрыть preview/состав корзины.
Уменьшить высоту/толщину нижней checkout-sheet до значения, соответствующего UX Guide проекта.
Сохранить поле телефона и элементы авторизации доступными для пользователя.
Сохранить текущую механику клавиатуры.
Использовать существующие UX-референсы проекта при выборе размеров и отступов.
Проверить поведение как при открытой, так и при закрытой клавиатуре.
Запрещено
менять сумму заказа;
менять состав заказа;
удалять товары из cart state;
менять Callcheck;
менять SMS fallback;
менять регистрацию;
менять авторизацию;
менять PaymentMethodsSheet;
менять общие checkout-thresholds без доказанной необходимости;
делать отдельный fork UI только для Callcheck.
5. Gherkin
Subtask 1: Phone-auth не показывает сумму заказа
Given пользователь находится на экране ввода телефона
When активен phone-auth wizard
Then CTA с суммой заказа не отображается.
Subtask 2: Phone-auth не показывает состав корзины
Given пользователь находится на экране ввода телефона
When активен phone-auth wizard
Then preview/состав корзины не отображается.
Subtask 3: уменьшенная checkout-sheet
Given пользователь находится на экране phone-auth
When открыта checkout-sheet
Then её высота соответствует UX-референсу проекта и не перекрывает рабочую область авторизации.
Subtask 4: клавиатура
Given пользователь вводит номер телефона
When системная клавиатура открыта
Then поле телефона и основные элементы wizard остаются доступны
And скрытые checkout-элементы не занимают место под wizard.
Subtask 5: возврат из phone-auth
Given пользователь завершил авторизацию
When wizard закрывается
Then checkout возвращается к своему обычному UI согласно существующему flow.
6. TDD-проверка
Минимально проверить:
существующие auth UI tests;
тест состояния CTA при активном phone-auth;
тест отсутствия cart preview при активном phone-auth;
существующие keyboard/UI tests;
мобильный viewport с открытой клавиатурой;
мобильный viewport без клавиатуры.
DoD:
на экране ввода телефона нет суммы заказа;
нет состава корзины;
sheet визуально соответствует UX Guide;
авторизация не затронута;
checkout после завершения auth работает как раньше;
существующие тесты зелёные.
Визуальный референс: скриншоты пользователя от 16.09.2026 + существующий UX Guide проекта.
