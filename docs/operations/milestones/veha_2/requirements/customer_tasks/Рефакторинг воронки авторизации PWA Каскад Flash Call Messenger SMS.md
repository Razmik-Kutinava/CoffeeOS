# Рефакторинг воронки авторизации PWA (Каскад Flash Call x2 → Messenger → SMS)

**Артефакты:** docs/operations/milestones/veha_2/artifacts/auth_funnel_cascade_flash_messenger_sms/

Бизнес-цель: Повысить конверсию регистрации у кассы за счет перехода к 2-экрановому Wizard с автоматическим 4-уровневым каскадом верификации (Flash Call #1 → Flash Call #2 → Мессенджер → СМС) без трения и лишних полей, снизив стоимость привлечения (CAC).

## Глобальные ограничения
- При построении UI/UX компонентов, экранов, отступов, цветовой гаммы, шрифтов и анимаций строго руководствоваться существующим UX Guide проекта. Новый интерфейс должен на 100% соответствовать утвержденному дизайн-коду.
- Запрещено использовать поле Email, радиокнопки ручного выбора канала и отдельные кнопки подтверждения кода.
- Запрещено хардкодить API-ключи провайдеров мессенджеров (использовать только ENV-переменные).

## Сценарии и чек-лист (Для todo.md)

- [ ] Шаг 1: Очистка UI и Экран 1 (Ввод номера телефона)
  - Given: Пользователь открыл экран авторизации. Старые элементы (Email, радиокнопки) удалены.
  - When: Пользователь взаимодействует с Экраном 1.
  - Then: Поле ввода имеет автофокус и маску `+7 (9XX) XXX-XX-XX`. Отображается единственная кнопка «Продолжить», которая активна строго при вводе 10 цифр. При клике отправляется запрос `POST /shop/api/phone_otp/send` с `channel: "flash_call"` и происходит бесшовный переход на Экран 2.

- [ ] Шаг 2: Экран 2 (Ввод кода и авто-сабмит)
  - Given: Пользователь перешел на Экран 2.
  - When: Пользователь вводит код или нажимает кнопку возврата.
  - Then: Отображается поле ввода из 4 отдельных ячеек/пина (согласно UX Guide). При вводе 4-й цифры происходит авто-сабмит `POST /shop/api/phone_otp/verify`. Отображается кнопка «Изменить номер», возвращающая на Экран 1. Отдельные кнопки подтверждения кода отсутствуют.

- [ ] Шаг 3: Стейт-машина каскада (Flash Call #1 и #2)
  - Given: Пользователь находится на Экране 2, запущен таймер каскада.
  - When: Проходит время или пользователь нажимает кнопки управления.
  - Then: 
    - **Шаг 1 (0–20 сек):** Отображается подсказка «Введите последние 4 цифры номера, с которого вам звонят. На звонок отвечать не нужно.» и текст таймера «Ждем звонок... 00:20».
    - **Шаг 2 (20–40 сек):** Отображается кнопка «Запросить звонок еще раз». При нажатии (или по таймауту) вызывается `POST` с `channel: "flash_call"`, запускается таймер на 20 секунд.

- [ ] Шаг 4: Стейт-машина каскада (Messenger и SMS Fallback)
  - Given: Прошло 40 секунд с начала верификации.
  - When: Наступает таймаут или пользователь нажимает кнопки переключения каналов.
  - Then: 
    - **Шаг 3 (40–70 сек):** Отображается кнопка «Получить код в WhatsApp / Telegram» (или срабатывает авто-запрос при истечении таймера). Подсказка: «Отправили 4-значный код в мессенджер на номер +7 (9XX) XXX-XX-XX». При нажатии: `POST` с `channel: "messenger"`, таймер на 30 секунд.
    - **Шаг 4 (70с+):** Отображается кнопка «Отправить код в СМС». Подсказка: «Отправили 4-значный код в СМС». При нажатии: `POST` с `channel: "sms"`, стандартный кулдаун 60 секунд.

- [ ] Шаг 5: Бэкенд: Интеграция мессенджеров и каналы
  - Given: Настроен сервис `Shop::MessengerClient` через ENV-переменные.
  - When: Поступает запрос `POST /shop/api/phone_otp/send` с `channel: "flash_call" | "messenger" | "sms"`.
  - Then: Эндпоинт принимает и обрабатывает все три канала. При ошибке доставки в мессенджер (4xx/5xx) API возвращает соответствующий флаг, чтобы фронтенд сразу предложил переход на шаг СМС. Запрос `POST /shop/api/phone_otp/verify` принимает `{ phone, code }`.

- [x] Шаг 6: Бэкенд: Кулдауны и Rate Limit
  - Given: Настроены `Rack::Attack` и сервис OTP.
  - When: Пользователь запрашивает повторную отправку кода.
  - Then: Применяются строгие кулдауны и rate limits: для `flash_call` — 20 секунд, для `messenger` — 30 секунд, для `sms` — 60 секунд. Превышение лимита блокирует запрос.

## Стратегия тестирования
- Фреймворк: RSpec (Backend Rails), Vitest/Jest (Frontend PWA).
- Путь к файлам тестов: `spec/` (Backend), `src/**/*.test.ts(x)` (Frontend).
- Критические кейсы: 
  - Frontend: Точные переходы стейт-машины по таймингам (20с, 20с, 30с), авто-сабмит ровно на 4-й введенной цифре, корректное отображение UX-подсказок и таймеров, обработка флага ошибки мессенджера для мгновенного перехода на SMS.
  - Backend: Корректная работа `Shop::MessengerClient`, обработка 4xx/5xx от провайдера мессенджеров, строгое соблюдение таймингов кулдаунов в `Rack::Attack` (20/30/60 сек) для каждого канала.

## Exit Criteria (Критерии выхода)
1. Все новые тесты проходят (зеленый статус).
2. Линтер и тайпчекер (tsc) выполняются без ошибок.
3. Интерфейс на 100% соответствует UX Guide (удалены Email/радиокнопки, внедрен 2-шаговый Wizard, 4-значный пин-код).
4. Автоматический 4-уровневый каскад (Flash Call #1 → Flash Call #2 → Messenger → SMS) работает без ручного выбора каналов.
5. При ошибке доставки в мессенджер (4xx/5xx) фронтенд корректно переключается на шаг СМС.
6. Rate limits и кулдауны на бэкенде строго соответствуют таймингам каналов (20с / 30с / 60с).
