## 1. Карта интеграций — затронуто / нет

Затронуто: маршрут "/o/:hash" ("OrderShortLinksController"); разбор результата "OrderReadySmsLink"; пользовательские состояния просроченной и недействительной ссылки; выбор точки при открытии ("bootstrapShopTenant"); документы TASK #39 и #82 (строки-уточнения).
Не затронуто: порядок каскада SMS; сборка текста SMS, подпись (HMAC) и срок жизни ссылки; SMS-провайдер, отправитель и ключи; FCM, WebPush, Wallet, регистрация push; платежи, checkout, Quick Repeat; объединение клиентов; startup flow за пределами выбора точки.

## 2. Текущее поведение — факты аудитов

- Маршрут: "GET /o/:order_hash → shop/order_short_links#show" ("config/routes.rb:21"). Порядок: проверка подписи и срока, "token_for", "bind!", редирект на "/shop?tenant_id=…&reconnect_token=…#/order/:id" (302, "allow_other_host: false"); точка берётся из "order.tenant_id" ("order_short_links_controller.rb:12-27").
- Разбор ссылки: декодирование, размер, сборка UUID, сравнение HMAC, поиск заказа (только mobile), затем проверка срока; любая неудача возвращает "nil" ("order_ready_sms_link.rb:32-49"). Просроченная, поддельная и повреждённая ссылки дают пустой 404 ("order_short_links_controller.rb:12-13"; тесты "order_short_links_test.rb:46-71").
- Срок: 48 часов от "ready_notified_at || ready_at || updated_at" ("order_ready_sms_link.rb:11,60-64"); ссылка не помечается использованной.
- Текст SMS в коде: «CODE:BLACK. Готов! {host}/o/{hash}» (префикс без хоста 19 символов, hash 27) ("order_ready_sms_link.rb:20-29,56-57"). В ТЗ #39 (":71") и #82 (":49"): «CODE:BLACK. Заказ готов! codeblack.xyz/o/{order_hash}».
- Хост: "SHOP_SMS_LINK_HOST" → "APP_HOST" → "coffeeos.fly.dev" ("order_ready_sms_link.rb:10,16-17"); на Fly задан только "APP_HOST=codeblack.coffee" ("fly.toml:10"); длина на prod 65 из 70. Лимит: "MAX_MSG_LENGTH = 70", проверка до HTTP ("sms_ru_client.rb:58,148-156", "order_ready_paid_notifier.rb:47-49"); тест запрещает "codeblack.xyz" ("order_ready_paid_notifier_test.rb:61").
- В ТЗ #39 и #82 нет нормы про повторное открытие ссылки.
- Клиент ("mobile_customers") один на платформу, в сессии он хранится ячейкой по точке ("customer_session.rb:4-16"); "/o/:hash" привязывает клиента до подтверждения ("guest_order_reconnect.rb:16-23"); безопасное подтверждение — отдельная задача.
- "bootstrapShopTenant" может заменить целевую точку сохранённой предпочитаемой ("shopTenantHeader.js:141-148,175-193"). Клиент параметр "reconnect_token" из адреса не читает.
- История: сейчас только текущая точка; история по сети — TASK-CODE-BLACK-CROSS-POINT-ORDER-HISTORY.
- Фактическое production RLS не подтверждено. Поведение ссылки из SMS при установленном приложении на iPhone не проверено (тест T1).

## 3. Scope

Разрешено: изменить цель редиректа с экрана заказа на историю заказов с параметром выделения ("#/profile?order=<id>"; выделение реализует TASK-CODE-BLACK-CROSS-POINT-ORDER-HISTORY); разбор ссылки возвращает причину неудачи (истекла или недействительна) после успешной проверки подписи; экраны сообщений для обоих случаев; приоритет точки заказа над сохранённой точкой; тесты; строки-уточнения в ТЗ #39 и #82.
Запрещено: менять порядок каскада; менять текст, отправителя и провайдера SMS; менять подпись, срок и якорь срока; делать ссылку одноразовой; удлинять текст SMS или менять хост без теста длины с реальным хостом из "fly.toml"; ослаблять проверку владельца и tenant isolation; открывать историю всех точек CoffeeOS; объединять записи клиентов; менять FCM, Wallet, checkout, платежи и Quick Repeat; создавать отдельный публичный ответ для поддельной ссылки, позволяющий проверять существование заказов.
Решения владельца: 2026-10-21 R1 — ссылка открывает историю с выделенным заказом; R4 — два сообщения: «ссылка устарела» (подпись верна, срок вышел) и «ссылка недействительна»; 2026-10-24 R7 А и R8 А — история по клиенту во всех точках сети, закрытые точки остаются. Домен остаётся фактическим (codeblack.coffee).
