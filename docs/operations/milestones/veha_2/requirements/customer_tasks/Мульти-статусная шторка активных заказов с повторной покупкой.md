# Мульти-статусная шторка активных заказов с повторной покупкой

Артефакты: `docs/operations/milestones/veha_2/artifacts/active_orders_accordion_repeat/`

**Бизнес-цель:** Предоставить пользователю возможность отслеживать статус активных заказов через разворачиваемую шторку-аккордеон на витрине PWA, просматривать детализированный чек и копировать состав в корзину через кнопку «Повторить».

## Глобальные ограничения
- Не менять структуру существующих эндпоинтов GET /shop/api/orders/active и /history (только расширить ответ)
- Не изменять глобальные стили PWA (шторка изолирована в компоненте)
- Не модифицировать логику корзины (только добавлять позиции через существующий API)
- Сохранить темную тему CoffeeOS (#1a1a1a фон, оранжевые акценты #ff6b35)

## Сценарии и чек-лист (Для todo.md)

### Блок A — Backend API

- [ ] Шаг A1: Расширить схему ответа GET /shop/api/orders/active
  - Given: Пользователь имеет 1+ активных заказов в БД
  - When: PWA запрашивает GET /shop/api/orders/active
  - Then: Ответ содержит массив заказов с полями: id, status, created_at, sales_point, items[] (product_id, name, quantity, price, modifiers[])

- [ ] Шаг A2: Реализовать POST /shop/api/orders/:id/repeat
  - Given: Заказ #ID существует и принадлежит пользователю
  - When: POST запрос с валидным auth token
  - Then: 
    - Бэкенд копирует order_items в корзину пользователя
    - Проверяет стоп-лист tenant_id, обновляет цены
    - Возвращает { added_items: [], skipped_items: [] }
  - Then (error 404): Заказ не найден → { error: "Order not found" }
  - Then (error 403): Заказ не принадлежит пользователю → { error: "Forbidden" }

- [ ] Шаг A3: Добавить валидацию стоп-листа в repeat endpoint
  - Given: Товар из заказа есть в стоп-листе точки
  - When: POST /shop/api/orders/:id/repeat
  - Then: Товар попадает в skipped_items, не добавляется в корзину

### Блок B — Frontend UI (PWA Bottom Sheet)

- [ ] Шаг B1: Создать компонент ActiveOrdersAccordion
  - Given: Массив активных заказов из API
  - When: Компонент монтируется
  - Then: Рендерятся карточки со статус-лайном (Принят → Оплачен → Готовится → Готов), время готовки, № заказа, точка продаж, стрелка-тогл (> / v)

- [ ] Шаг B2: Реализовать логику аккордеона (activeOrderId state)
  - Given: Заказ №1 развернут (expandedOrderId = ID_1)
  - When: Клик на стрелку заказа №2
  - Then: expandedOrderId = ID_2, чек №1 сворачивается с анимацией, чек №2 разворачивается

- [ ] Шаг B3: Добавить внутренний скролл чека
  - Given: Развернут чек с 10+ позициями
  - When: Пользователь скроллит содержимое
  - Then: Скролл внутри контейнера чека (max-height: 350px, overflow-y: auto), основная витрина не двигается

- [ ] Шаг B4: Реализовать кнопку «Повторить» для позиции
  - Given: Пользователь кликает «Повторить» у товара в чеке
  - When: POST /shop/api/orders/:id/repeat успешен (200)
  - Then: Позиция добавлена в корзину, шторка показывает состояние готовности к оплате

- [ ] Шаг B5: Обработать skipped_items при повторе
  - Given: Некоторые товары из чека в стоп-листе
  - When: POST /shop/api/orders/:id/repeat вернул skipped_items.length > 0
  - Then: Показать Snackbar: «Некоторые позиции сейчас нет в наличии, добавили доступные»

- [ ] Шаг B6: Обработать ошибки сети при повторе
  - Given: Пользователь кликает «Повторить»
  - When: Сеть недоступна или сервер вернул 500
  - Then: Показать ошибку «Не удалось повторить заказ, попробуйте позже», корзина не изменена

## Стратегия тестирования
- **Фреймворк:** Jest + React Testing Library (frontend), RSpec (backend)
- **Путь к файлам тестов:** 
  - Frontend: `src/components/ActiveOrdersAccordion/__tests__/`
  - Backend: `spec/requests/shop/api/orders_spec.rb`
- **Критические кейсы:**
  - Одновременное развертывание двух чеков (должен быть только один)
  - Скролл чека не влияет на скролл страницы
  - Repeat endpoint с пустым items массивом
  - Repeat endpoint с полностью недоступными товарами (все в skipped_items)
  - Асинхронное обновление статусов заказов (polling/websocket)

## Exit Criteria (Критерии выхода)
1. Все новые тесты проходят (зеленый статус): `yarn test` и `rspec spec/requests/shop/api/orders_spec.rb`
2. Линтер и тайпчекер выполняются без ошибок: `yarn lint` и `yarn tsc`
3. Шторка соответствует макету: темная тема, оранжевые кнопки, статус-лайн с 4 шагами
4. Изоляция открытого состояния: невозможно развернуть чеки двух заказов одновременно
5. Бесшовный повтор: клик «Повторить» добавляет позиции в корзину с валидацией стоп-листов

## Подписи к скринам заказчика (чат)

- один статус у заказа, шторка в режиме expanded
- 2 и боле статуса заказа в шторке expanded
