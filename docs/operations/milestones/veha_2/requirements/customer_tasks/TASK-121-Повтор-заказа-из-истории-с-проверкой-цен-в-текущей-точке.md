### 2. Карта компонентов

- "OrdersController": новое читающее действие (рабочее имя «превью повтора»): принимает id заказа, проверяет владельца ("OrderOwnership"), строит "CartService" на временной сессии (сервис принимает любой Hash-подобный объект сессии: "cart_service.rb:16-21") из позиций заказа (product_id, quantity, selected_modifiers) для текущей точки и возвращает по каждой позиции текущую цену за единицу с модификаторами ("unit_total"), "line_total", признак недоступности и общую сумму. Сессия гостя и корзина не изменяются; "GrowthPromo.price!" не вызывается (внутри "point_allows_promo?" есть "update_column(:counter, …)", "growth_promo.rb:155").
- "Profile.svelte" / "OrderReceipt.svelte": после несовпадения переход на главную страницу ("push('/')", не через "/payment-result").
- Сообщение на главной странице: через существующий механизм уведомлений витрины; если подходящего нет, небольшой закрывающийся блок над каталогом; состояние сообщения в памяти (не в localStorage).

### 3. Текущее поведение — факты аудита P
- Цепочка: "GET /orders/:id" → "runHistoryRepeatPayFlow" → "createOrderFromHistoryOrder": состав маппится в строки повтора, строки без "product_id" отбрасываются, количество ≤ 0 заменяется на 1 (":37-45,60"); без имени и email в профиле ошибка 422 (":65-71"); "DELETE /cart" (":73"); последовательный "addToCart" по каждой позиции без "try/catch" (":74-80"); "POST /orders" (card, "defer_payment_init", без "save_card" и цен) (":82-91"); оплата ("runRepeatWidgetPayFlow", ":174-179").
- Цены из исторического заказа не используются: клиент шлёт "product_id", "quantity", id модификаторов ("shopCartAdd.js:78-82"); сервер оставляет от модификатора только id и считает цену из БД: "ProductTenantSetting.price" плюс надбавки опций ("cart_service.rb:206-215,280-299"). Повтор всегда идёт по текущим ценам.
- Ответ "addToCart" с текущими "unit_total", "line_total", "total" адаптер отбрасывает ("historyRepeatAdapter.js:75", "shopCartAdd.js:89-93"). Сравнения цен или суммы нет.
- Корзина гостя очищается до проверки позиций; недоступный товар даёт "RecordNotFound" ("cart_service.rb:25-26"), корзина остаётся частично заполненной ("historyRepeatAdapter.js:212-230"). Корзина акцию не считает ("cart_service.rb:163"), эндпоинта расчёта без изменения корзины нет ("routes.rb:198-202").
- Хранение: "order_items" — "unit_price", "total_price", "quantity", "modifier_options" (jsonb), снимок "product_name"; "unit_price" включает модификаторы ("order_creator.rb:101-113", "schema.rb:586-600"); скидка только на уровне заказа ("total_amount", "discount_amount", "final_amount", "schema.rb:659-689"); промокоды не работают ("order_creator.rb:241-245,298").
- В заказе "price" — цена за единицу с модификаторами ("orders_controller.rb:248"), в корзине "price" — базовая без них ("cart_service.rb:155"), цене за единицу заказа соответствует "unit_total" (":159"). "order.total" = "final_amount" ("orders_controller.rb:233").
- Акция «11 ₽ на первый заказ» применяется только если запрошена привязка карты ("save_card", "order_creator.rb:59-61", "growth_promo.rb:11,31-44"); при повторе из ЛК "save_card" не передаётся ("historyRepeatAdapter.js:84-90"), поэтому по акции заказ не оформляется и списывается полная текущая сумма. "OrderReceipt" показывает строки с "line_total" и «Итого» = "final_amount" ("OrderReceipt.svelte:159-170"): у заказа по акции строки 450 ₽, «Итого» 11 ₽; "discount_amount" в разметке не выводится.
- Тестов на цены при повторе нет: тесты JS проверяют маппинг, порядок "DELETE /cart" → "addToCart" → "POST /orders" и навигацию после результата ("lk_history_repeat_one_click_test.mjs:54-211"); Ruby-тесты повтора — проверки по исходникам ("lk_history_repeat_one_click_test.rb:7-40").
- Риск вне этой задачи (не проверен на практике): "OrderCreator" может вернуть уже существующий pending-заказ сессии, если совпала только сумма "final_amount", состав не сверяется ("order_creator.rb:43-47,368-378").

### 4. Scope
Разрешено: проверка до любых изменений корзины и до создания заказа; серверное чтение текущих цен и наличия по позициям заказа в текущей точке; переход на главную страницу и сообщение; сохранность корзины гостя; тексты константами по конвенции проекта; тесты; актуализация тестов порядка вызовов "historyRepeatAdapter".
Запрещено: второй платёжный стек; изменение Init/Charge; изменение исходного заказа (PATCH); источник состава не из выбранного заказа; изменение "clearCartAfterSuccessfulPay", "OrderCreator", "GrowthPromo" и логики расчёта цен корзины; вызов "GrowthPromo.price!" и любых действий с побочными эффектами в превью; запись в сессию гостя в превью; автоматическая оплата при различии цен; кнопка «Оформить по новым ценам»; смена текущей точки; изменение Quick Repeat и общего FSM; показ скидки в чеке (отдельный вопрос).
Решения владельца: 2026-10-24 — «Повторить» выполняется в текущей точке; 2026-10-25 (R10) — при любом несоответствии (цены, сумма, заказ по акции «11 ₽») гость переходит на главную страницу и видит текст, что повторить заказ нельзя; кнопки «Оформить по новым ценам» нет. Недоступность позиций обрабатывается тем же механизмом (по умолчанию).
