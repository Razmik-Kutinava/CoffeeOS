# Отображение итоговой стоимости на кнопке корзины PWA


## Бизнес-контекст
В текущей версии PWA кнопка перехода к оформлению заказа содержит статичный текст «Оформить», а итоговая сумма вынесена в отдельный элемент. Пользователи не сразу замечают сумму платежа перед подтверждением покупки. Это приводит к дополнительным обращениям в службу поддержки и увеличивает долю отмененных заказов на этапе чекаута. Отображение суммы непосредственно на кнопке (в формате «+X₽», как показано в макете «+5 ₽») сделает процесс прозрачнее, снизит когнитивную нагрузку и повысит конверсию в успешную покупку.


## Сценарии и Критерии:


### Шаг 1. Инициализация кнопки с итоговой суммой
- [x] Заменить статичный текст «Оформить» на динамическое отображение суммы.
- [x] Обеспечить форматирование суммы с разделителями тысяч и знаком рубля.


**Сценарий 1.1: Отображение суммы при открытии корзины**
**Given** пользователь открыл экран PWA, в корзине есть товары на сумму 345 рублей
**When** пользователь видит нижнюю панель (или плавающую кнопку) корзины
**Then** кнопка подтверждения заказа отображает текст «+345₽»
**And** кнопка активна и доступна для нажатия
- [ ] **Тест-критерий (Assertion):** Проверить, что текст кнопки в DOM соответствует регулярному выражению `^\+\d{1,3}(?:\s?\d{3})*₽$` (например, «+345₽») и не содержит слова «Оформить». Проверить, что атрибут `disabled` отсутствует.
- [x] **Тест-критерий (Assertion):** Проверить, что текст кнопки в DOM соответствует регулярному выражению `^\+\d{1,3}(?:\s?\d{3})*₽$` (например, «+345₽») и не содержит слова «Оформить». Проверить, что атрибут `disabled` отсутствует.


### Шаг 2. Динамическое обновление суммы
- [ ] Обеспечить мгновенный пересчет суммы при изменении состава корзины.
- [ ] Синхронизировать значение на кнопке с общим итогом корзины.


**Сценарий 2.1: Изменение количества товара**
**Given** на экране отображается кнопка с текстом «+345₽»
**When** пользователь увеличивает количество одного из товаров на единицу
**Then** итоговая стоимость пересчитывается
**And** текст на кнопке мгновенно обновляется до актуальной суммы (например, «+450₽»)
- [ ] **Тест-критерий (Assertion):** Проверить, что после триггера изменения стейта корзины текст кнопки в DOM обновился до нового значения без полной перезагрузки страницы.


**Сценарий 2.2: Удаление товара из корзины**
**Given** на экране отображается кнопка с текстом «+450₽»
**When** пользователь удаляет товар из корзины
**Then** итоговая стоимость пересчитывается
**And** текст на кнопке обновляется до новой актуальной суммы
- [ ] **Тест-критерий (Assertion):** Проверить, что текст кнопки в DOM соответствует новой уменьшенной сумме.


### Шаг 3. Навигация по кнопке
- [ ] Сохранить существующий роутинг при нажатии на кнопку.


**Сценарий 3.1: Переход к оформлению заказа**
**Given** на экране отображается кнопка с актуальной итоговой суммой «+345₽»
**When** пользователь нажимает на эту кнопку
**Then** происходит переход на экран оформления заказа
**And** сумма заказа на следующем экране совпадает со значением, которое было отображено на кнопке
- [ ] **Тест-критерий (Assertion):** Проверить, что URL в адресной строке изменился на маршрут чекаута. Проверить, что глобальный стейт корзины сохранил значение суммы 345.


## Экстремальные сценарии:


**Сценарий: Пустая корзина или сумма 0₽**
**Given** в корзине PWA не осталось товаров
**When** пользователь находится на экране каталога или корзины
**Then** кнопка отображает текст «+0₽»
**And** кнопка переходит в неактивное состояние (disabled)
- [ ] **Тест-критерий (Assertion):** Проверить, что текст кнопки равен «+0₽» и атрибут `disabled` или класс блокировки присутствует в DOM.


**Сценарий: Ошибка API при пересчете корзины**
**Given** пользователь изменил количество товара
**When** запрос к API для пересчета суммы завершился с ошибкой (сетевая ошибка, таймаут, 500)
**Then** на кнопке отображается последняя валидная сумма (до изменения)
**And** отображается нативное уведомление об ошибке
- [ ] **Тест-критерий (Assertion):** Проверить, что текст кнопки в DOM не изменился после получения ответа с ошибкой от API. Проверить наличие DOM-элемента тоста/уведомления с текстом ошибки.


**Сценарий: Товар закончился (Out of stock) в процессе изменения**
**Given** пользователь добавил товар в корзину
**When** товар закончился на складе до момента подтверждения
**And** система обнаружила отсутствие товара при пересчете
**Then** товар удаляется из корзины
**And** сумма на кнопке пересчитывается без учета этого товара
- [ ] **Тест-критерий (Assertion):** Проверить, что текст кнопки в DOM обновился с учетом удаления товара. Проверить наличие DOM-элемента предупреждения о недоступности товара.


**Сценарий: Отмена действий (Undo)**
**Given** пользователь удалил товар из корзины
**And** сумма на кнопке обновилась
**When** пользователь нажимает кнопку «Отменить» в появившемся уведомлении
**Then** удаленный товар возвращается в корзину
**And** сумма на кнопке возвращается к предыдущему значению
- [ ] **Тест-критерий (Assertion):** Проверить, что после клика на «Отменить» текст кнопки в DOM вернулся к исходному значению.


**Сценарий: Потеря сети (Offline mode)**
**Given** пользователь находится в корзине PWA
**When** пропадает сетевое соединение
**Then** на кнопке отображается сумма из локального кэша (последнее известное состояние)
- [ ] **Тест-критерий (Assertion):** Проверить, что при эмуляции offline-режима текст кнопки в DOM остается равным последнему известному значению и не сбрасывается в «+0₽».


**Сценарий: Экстремально большая сумма (переполнение текста)**
**Given** итоговая стоимость заказа составляет 9 999 999 рублей
**When** текст суммы не помещается в стандартную ширину кнопки
**Then** размер шрифта суммы автоматически уменьшается
**And** базовые размеры и геометрия кнопки не нарушаются
- [ ] **Тест-критерий (Assertion):** Проверить, что ширина и высота DOM-элемента кнопки не изменились. Проверить, что текст «+9 999 999₽» полностью виден в DOM и не обрезан CSS-свойством `overflow: hidden`.
