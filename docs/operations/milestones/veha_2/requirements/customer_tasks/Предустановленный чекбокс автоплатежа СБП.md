## Текст заказчика (дословно)

Задача: Предустановленный чекбокс автоплатежа СБП

Бизнес-цель: Ускорить подключение автоплатежа для постоянных пользователей за счет предварительно установленного чекбокса «Привязать счет для покупок в один клик», не изменяя уже реализованную платежную логику, интеграцию с Т-Кассой и backend-контракты.

1. Связь с картой интеграций

- Затронутые сервисы из "@INTEGRATIONS.md": Т-Касса — косвенно, только через существующий параметр "save_sbp_account".
- Изменение интеграционного контракта: отсутствует.
- Смежные модули, которые НЕЛЬЗЯ ломать: существующий checkout flow, выбор способа оплаты, сохранение "AccountToken", Zero-Click Checkout, fallback на ручную оплату, корзина и расчет суммы заказа.

2. Разрешенный и Запрещенный Scope

- Разрешено менять/создавать:
  - "src/components/checkout/**/*"
  - "src/hooks/**/*" — только если состояние чекбокса реализовано через существующий checkout hook.
  - "src/components/checkout/**/*.test.tsx"
  - "src/hooks/**/*.test.ts"
- Строго запрещено менять:
  - backend API "/api/payments/init" и "/api/payments/charge"
  - логику "AccountToken"
  - интеграцию с Т-Кассой
  - "src/modules/payments/**/*"
  - "prisma/schema.prisma"
  - ".env" / ".env.example"
  - расчет суммы заказа
  - существующую логику fallback и обработки ошибок платежа.

3. Сценарии и Чек-лист (Gherkin)

- [ ] Subtask 1: Установить чекбокс автоплатежа включенным по умолчанию
  
  - Given: Пользователь открывает экран выбора способа оплаты, отображается чекбокс «Привязать счет для покупок в один клик».
  - When: Экран впервые отображается и пользователь ранее не изменял состояние чекбокса в рамках текущего checkout flow.
  - Then: Чекбокс отображается в состоянии "checked=true". Остальная верстка и логика экрана не изменяются.

- [ ] Subtask 2: Сохранить возможность отключить автоплатеж перед оплатой
  
  - Given: Чекбокс отображается установленным по умолчанию.
  - When: Пользователь снимает чекбокс и нажимает «Оплатить быстро».
  - Then: В существующий payment flow передается "save_sbp_account=false". Backend-контракт не изменяется.

- [ ] Subtask 3: Передать включенное состояние автоплатежа в существующий flow
  
  - Given: Чекбокс установлен по умолчанию и пользователь его не снимает.
  - When: Пользователь нажимает «Оплатить быстро».
  - Then: В существующий payment flow передается "save_sbp_account=true", после чего выполняется текущая реализация Setup без изменений backend-логики.

- [ ] Subtask 4: Не сбрасывать состояние чекбокса после UI-перерисовки
  
  - Given: Чекбокс был установлен по умолчанию, пользователь снял его.
  - When: Checkout-компонент перерисовывается из-за изменения способа оплаты или другого UI-state.
  - Then: Чекбокс остается снятым и не возвращается автоматически в "checked=true".

4. Команды TDD-проверки

- Запуск тестов: "npm test src/components/checkout"
- Проверка типов: "npx tsc --noEmit"
- Проверка линтера: "npm run lint"

5. Критерии выхода

1. При открытии выбора оплаты чекбокс «Привязать счет для покупок в один клик» установлен заранее.
2. Пользователь может снять чекбокс перед оплатой.
3. Снятый чекбокс передает существующий "save_sbp_account=false".
4. Оставленный установленным чекбокс передает существующий "save_sbp_account=true".
5. Backend, БД и интеграция Т-Кассы не изменяются.
6. Существующая логика Zero-Click Checkout и fallback не регрессирует.
7. При UI-перерисовке состояние, измененное пользователем, не сбрасывается.
