# Мульти-статусная шторка активных заказов с просмотром состава чека

Артефакты: `docs/operations/milestones/veha_2/artifacts/active_orders_accordion_receipt/`

**Бизнес-цель:** Предоставить пользователю возможность отслеживать статус активных заказов через разворачиваемую шторку-аккордеон на витрине PWA и просматривать детализированный состав чека (товары, модификаторы, скидки, итоговая сумма) без перехода на сторонние экраны.

## Глобальные ограничения
- Не менять структуру существующих эндпоинтов GET /shop/api/orders/active и /history (только расширить ответ)
- Не изменять глобальные стили PWA (шторка изолирована в компоненте)
- Не добавлять интерактивные элементы в блок чека (только текстовое отображение)
- Сохранить темную тему CoffeeOS (#1a1a1a фон, оранжевые акценты #ff6b35)

## Сценарии и чек-лист (Для todo.md)

### Блок A — Backend API

- [ ] Шаг A1: Расширить схему ответа GET /shop/api/orders/active
  - Given: Пользователь имеет 1+ активных заказов в БД
  - When: PWA запрашивает GET /shop/api/orders/active
  - Then: Ответ содержит массив заказов с полями: id, status, created_at, sales_point, items[] (product_id, name, quantity, price, modifiers[]), subtotal, discount, total_amount

- [ ] Шаг A2: Добавить детализацию модификаторов в items
  - Given: Заказ содержит товары с выбранными сиропами/модификаторами
  - When: PWA запрашивает GET /shop/api/orders/active
  - Then: Каждый item содержит modifiers[] с name и price для каждого модификатора

### Блок B — Frontend UI (PWA Bottom Sheet)

- [ ] Шаг B1: Создать компонент ActiveOrdersAccordion
  - Given: Массив активных заказов из API
  - When: Компонент монтируется
  - Then: Рендерятся карточки со статус-лайном (Принят → Оплачен → Готовится → Готов), время готовки, № заказа, точка продаж, стрелка-тогл (> / v)

- [ ] Шаг B2: Реализовать жесткое правило «Открыт только один» (activeExpandedOrderId)
  - Given: Заказ №1 развернут (activeExpandedOrderId = ID_1)
  - When: Пользователь кликает на стрелку заказа №2
  - Then: activeExpandedOrderId = ID_2, чек №1 закрывается, чек №2 открывается. Одновременно два чека быть не может.

- [ ] Шаг B3: Добавить внутренний скролл текстовой карточки чека
  - Given: Развернут чек с длинным составом позиций
  - When: Пользователь скроллит содержимое чека
  - Then: Скроллится только содержимое текста чека (max-height: 350px, overflow-y: auto). Вся шторка, соседние заказы и витрина PWA не сдвигаются.

- [ ] Шаг B4: Отобразить текстовую структуру чека
  - Given: Чек развернут
  - When: Компонент рендерит состав заказа
  - Then: Каждая позиция отображает: Наименование → Модификаторы → Кол-во → Цена → Скидка → Итого уплачено (без кнопок действий)

- [ ] Шаг B5: Отобразить финансовые итоги чека
  - Given: Чек развернут
  - When: Компонент рендерит итоги
  - Then: Внизу чека отображаются: Subtotal, Discount, Total Amount

## Стратегия тестирования
- **Фреймворк:** Jest + React Testing Library (frontend), RSpec (backend)
- **Путь к файлам тестов:** 
  - Frontend: `src/components/ActiveOrdersAccordion/__tests__/`
  - Backend: `spec/requests/shop/api/orders_spec.rb`
- **Критические кейсы:**
  - Одновременное развертывание двух чеков (должен быть только один)
  - Скролл чека не влияет на скролл страницы
  - Отображение чека с пустым массивом items
  - Отображение чека с товарами без модификаторов
  - Отображение чека с нулевой скидкой
  - Асинхронное обновление статусов заказов (polling/websocket)

## Exit Criteria (Критерии выхода)
1. Все новые тесты проходят (зеленый статус): `yarn test` и `rspec spec/requests/shop/api/orders_spec.rb`
2. Линтер и тайпчекер выполняются без ошибок: `yarn lint` и `yarn tsc`
3. Изоляция состояния: при наличии 2+ заказов всегда развернут максимум 1 чек
4. Внутренний скролл: содержимое чека скроллится внутри блока (max-height: 350px), не раздувая шторку
5. Чистый UI чека: блок чека содержит только текстовые данные, без интерактивных кнопок
