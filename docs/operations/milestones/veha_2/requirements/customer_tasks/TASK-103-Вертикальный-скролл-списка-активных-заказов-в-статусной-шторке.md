TASK_103: Вертикальный скролл списка активных заказов в статусной шторке

Бизнес-цель: дать пользователю просматривать все активные заказы в ограниченной по высоте статусной шторке, не раскрывая чек и не сдвигая содержимое корзины или основного экрана.

3. Текущее поведение (факт аудита)

При двух активных заказах с закрытыми чеками ".oss__panel" не получает "overflow-y: auto". При количестве заказов больше двух включается класс "scrollable"; при открытии чека — "receipt-open". Отдельного контейнера прокрутки списка нет.

4. Scope

Разрешено:

- Реализовать вертикальную прокрутку списка при двух и более активных заказах, в том числе когда все чеки закрыты.

## Заметки агента

### Решение по открытому риску (владелец 2026-10-09: «вот же ты написал как решил как нужно»)

`fitReceiptInView` (чистая функция) и вызывающий её `measureReceiptFit` в `ActiveOrdersAccordion.svelte` прокручивают **только новый внутренний контейнер списка** `.oss__list`, не `.oss__panel` и не основной экран. Это снимает блокер «не готов к Build».

- `.oss__panel` — рамка фиксированной peek-высоты (`max-height` как сейчас), сама не скроллится (`overflow: hidden`), классы `scrollable` / `receipt-open` больше не дают ей `overflow-y: auto`.
- `.oss__list` — обёртка над `{#each displayOrders}`: `overflow-y: auto`, `overscroll-behavior: contain`, `min-height: 0` (flex-колонка внутри панели). Скролл всегда включён — при двух заказах и при закрытых чеках.
- `measureReceiptFit` ищет контейнер явно (`el.closest("[data-oss-scroll-root]")`), а не «ближайший предок с overflow auto» — контракт не зависит от CSS панели.
- Порог `shouldScrollStatusList` `> 2` → `> 1`: управляет только подсказкой `↕`; сам скролл от порога не зависит.

### Ограничение тестового стека (§6)

`test/system` в репо нет, в CI job `system-test` пропускается («полный test:system падает на setup» — `.github/workflows/ci.yml:200`). Node-тесты — SSR без layout. Поэтому фактическая прокрутка проверяется **скриптом в реальном браузере** (Cursor browser + CDP `Runtime.evaluate`, 390×844, локальный Point A) с замером `scrollTop` у `.oss__list` / `.oss__panel` / `window` → `artifacts/active_orders_list_scroll/MEASURE.md`; плюс ручная проверка на телефоне после deploy по апруву.
