## Текст заказчика (канон — без сокращений)

[Режим "hidden" не отображает превью товаров — карточки пустые или некорректно обрезаны. Необходимо реализовать корректное усечение изображения товара в режиме hidden согласно UX-паттернам проекта]

### Глобальные ограничения

- Не менять существующие UX-паттерны из cursorules (peek/expanded режимы работают корректно)
- Не изменять структуру данных товаров
- Сохранить текущую типографику и цветовую схему
- Не ломать работу режимов peek и expanded

### Сценарии реализации (Use Cases в Gherkin)

**Сценарий 1: Отображение карточки в режиме hidden**

- [ ] Given: Товар имеет изображение (фото кофе/напитка)
- [ ] When: Карточка переключается в режим hidden
- [ ] Then: Отображается усеченная версия изображения (crop по центру или top), видна часть товара, карточка занимает минимальную высоту

**Сценарий 2: Карточка без изображения в режиме hidden**

- [ ] Given: Товар не имеет изображения (placeholder "Нет фото")
- [ ] When: Карточка отображается в режиме hidden
- [ ] Then: Показывается placeholder с текстом "Нет фото" на темном фоне, сохраняется структура карточки

**Сценарий 3: Переключение между режимами**

- [ ] Given: Пользователь видит карточку в режиме hidden
- [ ] When: Происходит свайп/клик для перехода в peek или expanded
- [ ] Then: Изображение плавно масштабируется до полного размера, контент раскрывается без скачков

**Сценарий 4: Горизонтальный скролл категорий**

- [ ] Given: Пользователь находится в разделе "Холодные" или "Фильтр-кофе"
- [ ] When: Карточки отображаются в режиме hidden в горизонтальном списке
- [ ] Then: Все карточки имеют одинаковую высоту, изображения обрезаны пропорционально, видны названия и цены

### Экстремальные сценарии (Error & Edge States)

- [ ] При загрузке изображения с задержкой — показывать skeleton loader в режиме hidden
- [ ] Если изображение не загрузилось (404/500) — fallback на placeholder "Нет фото"
- [ ] При очень длинном названии товара — текст обрезается с многоточием (...), не вылезает за границы карточки
- [ ] При изменении ориентации устройства — карточки пересчитывают размеры, сохраняя режим hidden
- [ ] Если товаров в категории нет — показывать пустое состояние с сообщением

### Критерии авто-выхода (Exit Criteria)

1. Код проходит unit/интеграционные тесты под эти сценарии
2. Проверка типов TypeScript (tsc) и линтер проходят без ошибок сборки
3. Визуальная проверка: режим hidden показывает усеченное изображение как на 3-м скриншоте (CoffeeOS, разделы "Черный", "Холодные")
4. Анимация перехода между hidden → peek → expanded работает плавно (60fps)
5. Все карточки в горизонтальном скролле имеют одинаковую высоту в режиме hidden
6. Мобильная и десктоп версии отображаются корректно
