## Проблема

В текущей реализации карточки товара «Фильтр-кофе Бразилия» (CoffeeOS) пользователь вынужден выбирать модификаторы из групп «Температура», «Вкус» и «Интенсивность» перед добавлением товара в корзину — поля помечены как «*обязательно». Это создаёт барьер: клиент не может добавить базовый товар без дополнительных опций, что противоречит сценарию быстрой покупки «одним нажатием». Кроме того, текущая логика «предварительного нажатия» модификатора (сначала выбрать, потом нажать «В корзину») увеличивает количество кликов и усложняет UX.

### Наблюдения на скрине «до»

- Коричневый баннер: «Сначала выберите параметры с пометкой **обязательно**…»
- У групп **Температура / Вкус / Интенсивность** — подпись **«· обязательно»**
- Чипы модификаторов без явного toggle-индикатора «+»
- «В корзину» блокируется, пока не заполнены обязательные группы (`missingRequiredGroups` в `Product.svelte`)
- `defaultSelectionForGroup` в `modifiers.js` **автовыбирает первый модификатор** в radio/required группах — пользователь не может остаться с «чистым» товаром

## Решение

### Продуктовые требования

- Пользователь получает возможность добавить товар в корзину **без выбора модификаторов** — ускоряет сценарий быстрой покупки.
- Пользователь получает возможность гибко управлять модификаторами: **добавлять и убирать одним нажатием** (toggle).
- Увеличение конверсии в корзину за счёт снижения трения на этапе выбора опций.

### Технологические требования

- Изменение применяется к компоненту карточки товара на фронте CoffeeOS.
- Логика валидации обязательных модификаторов **удалена на уровне UI**.
- Состояние модификатора — boolean / выбран-не выбран в стейте компонента (`selected`).
- Итоговая цена на карточке пересчитывается: база + сумма наценок выбранных модификаторов.

### User Story

Как покупатель CoffeeOS, я хочу добавлять и убирать модификаторы (температуру, вкус, интенсивность) одним нажатием на карточку опции, чтобы быстро кастомизировать напиток **без обязательного выбора** и без лишних шагов перед добавлением в корзину.

### Use Case

1. Пользователь открывает карточку товара «Фильтр-кофе Бразилия».
2. Пользователь видит группы модификаторов: «Температура», «Вкус», «Интенсивность». Пометка «*обязательно» **отсутствует**.
3. Пользователь нажимает на карточку модификатора (например, «Топинамбур — нейтральная сладость без послевкусия +30₽»).
4. На карточке модификатора появляется индикатор выбора «+» (или визуальное выделение), модификатор добавлен к заказу.
5. Пользователь нажимает на тот же модификатор повторно — индикатор «+» исчезает, модификатор удалён из заказа.
6. Пользователь нажимает «В корзину» — товар добавляется с учётом выбранных модификаторов (либо **без них**, если ни один не выбран).

### Corner cases

| # | Сценарий | Решение до апрува |
|---|----------|-------------------|
| CC-1 | Несколько модификаторов в одной группе | **Ответ заказчика:** можно выбрать **сколько угодно** вкусов (и модификаторов) в группе — **ограничения нет** (multi toggle). |
| CC-2 | Вернулся в карточку после add в корзину | Сейчас стейт **сбрасывается** при смене route (`$effect` на `params.id`). **Вне scope** ТЗ заказчика; зафиксировать как known limitation или отдельный хвост. |
| CC-3 | Модификатор с наценкой (+30₽, +66₽) | Цена в нижнем баре = база + сумма выбранных; допуск ±0.01₽ |
| CC-4 | Пустой `selected_modifiers` в корзине | API уже принимает `[]` — проверено на BR-5 / Fly |

### Ограничения (чего не делаем)

- Не меняем ассортимент модификаторов и их цены.
- Не меняем логику расчёта итоговой стоимости заказа на бэкенде — только передаём актуальный состав модификаторов.
- Не затрагиваем другие экраны (витрину-листинг, корзину, оформление) — **только карточку товара**.
