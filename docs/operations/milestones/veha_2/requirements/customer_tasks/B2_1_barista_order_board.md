## Проблема (заказчик)

Табло в формате to-do list: ручное перетаскивание, нет крупной кнопки статуса, нет цветовой обратной связи, модификаторы не видны, нет FIFO, гость не всегда получает понятный статус, нет механик исключений в карточке.

---

## Решение (текст заказчика)

### Блок 1. Интерактивная карточка

- Квадратный блок фиксированного размера: номер, время, состав с модификаторами (**+ ПО КРЕПЧЕ** / **БЕЗ Сахара**).
- Кнопка ≥ 80 px: «Оплачен» → **ГОТОВИТСЯ**; «Готовится» → **ГОТОВ**.
- Цвет: оплачен — синий; готовится — оранжевый; готов — зелёный.

### Блок 2. FIFO

- Очередь по `created_at`, без ручного reorder.
- При смене статуса карточка переходит в следующую колонку.

### Блок 3. Уведомления клиенту

- «Оплачен» → «Готовится»: **«Ваш заказ начали готовить»**.
- «Готовится» → «Готов»: **«Заказ готов, забирайте!»**
- WebSocket; при сбое — повтор до 3 раз, интервал 5 с.

### Блок 4. Исключения

- **Отмена (MVP упрощённо):** overlay «СТОП! ЗАКАЗ ОТМЕНЁН», подтверждение; без звука/списания.
- **Брак / переделка / возврат:** фаза 2/3.

### Ограничения

- Цепочка: Принят → Оплачен → Готовится → Готов.
- Без ручного порядка и произвольного следующего статуса.
- Брак — не бариста (фаза 2/3).

### Баг-репорт 1: TO-DO список вместо 6 карточек

**Тема:** Некорректная реализация механики табло баристы — отображение заказов в виде TO-DO списка вместо 6 карточек с управлением статусом через касание

На экране табло баристы заказы отображаются в виде TO-DO списка вместо 6 фиксированных карточек с изменением цвета при касании для управления статусом готовки

#### Описание

**Шаги к воспроизведению:**
1. Открыть экран табло баристы на планшете.
2. Оформить и оплатить заказ на веб-сайте.
3. Дождаться появления заказа на экране табло баристы.
4. Проверить формат отображения заказа (список или карточки).
5. Проверить количество одновременно отображаемых заказов.
6. Коснуться карточки заказа для смены статуса.
7. Проверить изменение цвета карточки.
8. Коснуться карточки повторно для завершения заказа.
9. Проверить удаление карточки с экрана.
10. Проверить наличие информации в карточке: номер заказа, имя клиента (если введён номер телефона), название товара, модификатор (если имеется).

**Фактический результат:**
На экране табло баристы заказы отображаются в виде TO-DO списка. Заказы накапливаются на экране после завершения. Отсутствует механика изменения цвета карточки при касании (белый → жёлтый → удаление). Карточки не имеют фиксированного размера и расположения на экране. Отсутствует ограничение в 6 одновременно отображаемых заказов.

**Ожидаемый результат:**
На экране табло баристы заказы отображаются в виде 6 фиксированных карточек (квадратиков), расположенных на экране без возможности перемещения.

**Состав карточки:**
- Номер заказа
- Имя клиента (если введён номер телефона)
- Название карточки товара
- Модификатор (если имеется)

**Механика работы:**
- При поступлении заказа карточка отображается белым цветом.
- При касании карточки пальцем (принятие заказа в работу) карточка меняет цвет на жёлтый.
- При повторном касании карточки (заказ завершён) карточка удаляется с экрана.
- Завершённые заказы не накапливаются на экране.
- Одновременно на экране отображается не более 6 карточек.

*Пример отображения карточек приложен к задаче.*

### Баг-репорт 2: нет live без F5

**Тема:** Новый заказ не отображается на табло баристы (кухни) при поступлении без ручного обновления страницы

#### Описание

**Шаги к воспроизведению:**
1. Открыть экран табло баристы (кухни) на планшете или терминале.
2. Оформить и оплатить новый заказ через веб-сайт или PWA клиента.
3. Оставить экран табло баристы без действий (не обновлять страницу браузера).
4. Наблюдать за появлением карточки нового заказа на экране табло.

**Фактический результат:**
Новый заказ не появляется на экране табло баристы. Карточка заказа отображается только после принудительного ручного обновления страницы (F5 / свайп вниз).

**Ожидаемый результат:**
Новый заказ автоматически и мгновенно появляется на экране табло баристы в виде карточки сразу после оплаты на клиентской стороне, без необходимости ручного обновления страницы. Ожидается корректная работа механизма real-time синхронизации (WebSocket / Server-Sent Events).

**Требование:** Функциональное требование «Автоматическое поступление заказов на табло в реальном времени»
