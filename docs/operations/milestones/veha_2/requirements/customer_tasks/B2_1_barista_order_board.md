## Проблема (заказчик)

В текущей системе табло бариста карточка заказа отображается в формате to-do list: бариста перемещает заказы по столбцам статусов. Нет крупной кнопки смены статуса, нет визуальной обратной связи через цвет карточки, нет явного отображения модификаторов рецепта (добавленные/убранные ингредиенты). Заказы не выстроены в очередь FIFO. При смене статуса клиент не всегда получает понятную обратную связь. Нет встроенных механик исключений (отмена, брак, переделка, возврат) в карточке.

## Решение (текст заказчика — без сокращений)

### Продуктовые требования

#### Блок 1. Интерактивная карточка заказа

- Каждая карточка заказа на табло представляет собой единый квадратный блок фиксированного размера.
- Карточка содержит:
  - Номер заказа и время создания.
  - Состав заказа с модификаторами: добавленные — капс + жирный + контрастный фон (**+ ПО КРЕПЧЕ**); удалённые — зачёркивание (**БЕЗ Сахара**).
  - Крупная кнопка смены статуса внизу (≥ 80 px, на всю ширину). Текст: «Оплачен» → **ГОТОВИТСЯ**; «Готовится» → **ГОТОВ**.
  - Цвет фона карточки по статусу:
    - «Принят» — серый;
    - «Оплачен» — синий;
    - «Готовится» — оранжевый;
    - «Готов» — зелёный.
- По нажатию кнопки карточка меняет цвет.

#### Блок 2. FIFO-очередь

- Заказы с веб-сайта в очереди FIFO по `created_at`.
- Ручное перетаскивание порядка **запрещено**.
- Порядок на экране: слева направо, сверху вниз.
- При смене статуса карточка уходит из колонки и появляется в следующей.

#### Блок 3. Уведомления клиенту

- При смене статуса баристой — уведомление на веб-сайт:
  - «Оплачен» → «Готовится»: «Ваш заказ начали готовить».
  - «Готовится» → «Готов»: «Заказ готов, забирайте!»
- WebSocket в реальном времени; при сбое — повтор до 3 раз, интервал 5 с.

#### Блок 4. Исключения (отмена, брак, переделка, возврат)

- **Отмена:** карточка блокируется, тёмно-серый, «СТОП! ЗАКАЗ ОТМЕНЁН», звук, кнопка «ПОДТВЕРДИТЬ ОТМЕНУ», черновик списания.
- **Брак / переделка:** кнопка «БРАК», справочник причин, списание со склада, возврат в начало очереди «Готовится», бейдж «ПЕРЕДЕЛКА».
- **Возврат:** через интерфейс брака + пометка «ВОЗВРАТ ОТ КЛИЕНТА».

### Технологические требования (заказчик)

- Карточка как компонент с `status`, `customizations`, `queue_position`.
- Очередь синхронизируется через WebSocket.
- `POST /api/orders/{id}/status` — у нас: `PATCH /barista/orders/:id` + `OrderStatusUpdateService`.
- Уведомления: WebSocket + fallback push (PWA — **не MVP**).
- `defect_reasons` — **не MVP**.
- Звук при отмене — **фаза 2/3**.
- `status_changed_at` с точностью до мс — через `OrderStatusLog`.

### Ограничения (заказчик)

- Не менять цепочку: Принят → Оплачен → Готовится → Готов.
- Не давать ручной порядок в очереди.
- Не давать выбор произвольного следующего статуса.
- Брак — не бариста, только менеджер/упаковщик (**фаза 2/3**).
- Причина брака только из справочника (**фаза 2/3**).

## Маппинг CoffeeOS: статусы ↔ колонки

| Колонка UI | `Order.status` | Цвет карточки (MVP) | Кнопка |
|------------|----------------|---------------------|--------|
| ACCEPTED | `accepted` | синий (# — уточнить в макете) | ГОТОВИТСЯ → `preparing` |
| PREPARING | `preparing` | оранжевый | ГОТОВ → `ready` |
| READY | `ready` | зелёный | Выдать → `issued` (как сейчас, без нового экрана) |

На табло попадают заказы **с витрины** (`source: mobile`) после оплаты и заказы **с ручного создания** бариста (после B2.2 — только безнал).
