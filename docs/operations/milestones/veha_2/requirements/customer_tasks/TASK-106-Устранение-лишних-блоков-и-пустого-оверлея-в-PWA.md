TASK_106: Устранение лишних блоков и пустого оверлея в PWA

Основание: аудит геометрии PWA и изолированные замеры на Google Pixel 6 в Google Chat, 2026-10-09

Бизнес-цель: освободить полезную площадь экрана PWA, устранить перекрытие каталога и нижней панели корзины лишними UI-блоками, сохранив предусмотренное UX/UI расположение рабочих элементов и корректное поведение остальных сценариев.

1. Карта интеграций — затронуто / нет

- Затронуто: клиентская вёрстка PWA, товарная шторка, логика отображения повторных покупок, вызов пустого оверлея с индикатором-полоской.
- Серверные API и бизнес-расчёты: не менять.
- Оплата, сумма корзины, оформление заказа: не менять, кроме сохранения доступности существующей панели после удаления перекрывающих элементов.
- Перед Build сверить актуальную карту интеграций: "docs/integrations/INTEGRATIONS.md".

2. Карта компонентов — затронуто / границы

По результатам аудита:

- "CartSheet.svelte" — общая шторка корзины; изменение её геометрии может затронуть каталог, товарный экран, Quick Repeat и сценарии оплаты.
- "cartSheetThresholds.js" — пороги и высоты шторки; менять только если аудит кода подтвердит, что после удаления блока прежние значения больше не соответствуют фактическому содержимому.
- "Product.svelte" и связанный компонент товарной шторки — проверить фактическое место рендеринга блока рекомендаций «повторить».
- Компонент или условие, вызывающее пустой оверлей с индикатором-полоской, — точное имя и место вызова установить по коду до Build.

Общий файл с другими задачами: да. "CartSheet.svelte" и связанные пороги используются несколькими сценариями. Границу изменений соблюдать одинаково в этом документе и при последующем обновлении "COMPONENT_MAP.md".

Новый компонент: не требуется.

3. Текущее поведение (факт)

Проблема 1 — рекомендации «повторить» в товарной шторке

По изолированному замеру на Google Pixel 6 в Google Chat блок рекомендаций «повторить» под целевой кнопкой «добавить к заказу» занимает около 320 px, то есть приблизительно 35% полезной площади viewport.

Проблема 2 — пустой оверлей

По изолированному замеру пустой слой с индикатором-полоской занимает около 110 px, то есть приблизительно 12% экрана. Он перекрывает плашку «Итого 0₽» и категорию «Холодные».

Указанные значения — результаты замера конкретного устройства и WebView; не считать их универсальными CSS-высотами для всех устройств.

4. Scope

Разрешено

1. Полностью исключить блок рекомендаций «повторить» из вёрстки товарной шторки.
2. После исключения блока уменьшить высоту товарной шторки на величину действительно освобождённого пространства.
3. Проверить и при необходимости скорректировать расчёт высоты шторки так, чтобы она соответствовала оставшемуся содержимому, без искусственного сохранения удалённой высоты.
4. Найти и полностью отключить вызов пустого оверлея с индикатором-полоской, если подтверждено, что слой не выполняет нужной функции в проверяемом сценарии.
5. Удалить связанный с этими элементами резерв пространства, если он предназначен только для исключённых блоков и его удаление не нарушает safe-area и жесты шторки.
6. Добавить регрессионные тесты, подтверждающие отсутствие удалённых элементов и доступность ранее перекрываемых элементов.

Запрещено

- Не удалять Quick Repeat из остальных экранов и сценариев, если он не относится к товарной шторке.
- Не менять алгоритмы повторения заказа, данные корзины, расчёт "cartTotal", цены, скидки и оплату.
- Не менять подпись, действие и расположение кнопки «добавить к заказу», кроме изменений высоты контейнера, необходимых для удаления лишнего блока.
- Не менять общие пороги "CartSheet" без доказанной необходимости по коду и тестам.
- Не менять минимальный safe-area снизу, системные отступы WebView и зону жеста.
- Не менять "phoneAuthSlim", поведение при открытой клавиатуре, стек оплаты и режимы peek/expanded.
- Не удалять другие оверлеи, полоски-индикаторы или элементы жестов только из-за внешнего сходства. Отключается только идентифицированный пустой слой из Проблемы 2.
- Не менять "PaymentMethodsSheet", экран фискального чека и экран статуса заказа.
- Не вносить изменения в "COMPONENT_MAP.md" до успешного Review и зелёных тестов.
