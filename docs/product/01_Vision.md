CoffeeOS — **цифровая ОС для сети кофеен**, не просто касса. Система держит стандарты бренда, связывает витрину, кассу, цех и УК в одном контуре.

## 1. Миссия и концепция

CoffeeOS — это не просто кассовое решение, а цифровая операционная система для ресторанов (Restaurant Operating System). Наша цель — предоставить бизнесу инструмент «цифровой франшизы», который позволяет масштабировать сеть кофеен без потери качества, минимизировать человеческий фактор и обеспечить полную прозрачность операций.

Мы строим систему, которая превращает хаос ручного управления в алгоритмизированный бизнес-процесс.

## 2. Целевая аудитория (Personas)

**Франчайзи — Менеджер офиса (`franchise_manager`):** управляет группой своих точек. Нуждается в консолидированной аналитике в реальном времени (выручка, Labour Cost, скорость производства, рейтинг качества) для контроля эффективности бизнеса без операционного доступа к кассам. **В демо:** панель `/manager`, переключение точек сети.

**Управляющий точки (`general_manager`):** полностью отвечает за жизнедеятельность одной конкретной локации. Инструменты долгосрочного планирования и настройки: меню и локальные цены, складской учёт, кадры, финансовые срезы. **В демо:** полный доступ manager.

**Менеджер смены (`shift_manager`):** руководитель кофейни на линии горизонта «Сегодня». Оперативка текущей открытой смены: стоп-листы, устройства, проблемы с заказами. **В демо:** `/manager` в рамках открытой смены.

**Бариста (`barista`):** линейный сотрудник на POS. Быстрый интерфейс, кассовая дисциплина внутри открытой смены. **В демо:** `/barista` + live-табло.

**Работник цеха (`prep_kitchen_worker`):** заготовочный цех — движения склада, стоп-листы. **В демо:** `/prep_kitchen`.

## 3. Ключевые столпы продукта (Core Pillars)

### I. Цифровая франшиза и стандартизация

Система — носитель стандартов бренда: рецептуры, цены, модификаторы, регламенты — из УК на все точки сети.

**Результат:** идентичное качество продукта в любой точке, независимо от опыта персонала.

### II. Непрерывность бизнеса (Zero-Downtime) — цель, **Веха 3**

Для QSR простой системы = потеря прибыли. Целевая архитектура — **Offline-first**.

**Веха 1–2:** все каналы работают **только online** (HTTP). Offline, Drift/Hive и очередь синхронизации — **В3**.

### III. Анти-фрод и прозрачность

Полный Event Sourcing склада и ночная сверка — **Веха 3**.

**Веха 1–2 (база):** заказы баристы привязаны к `CashShift`; POS без открытой смены запрещён; отмена с обязательной причиной и записью в `admin_audit_logs`; сверка наличности при закрытии смены (`cash_difference`); журнал платежей и событий в УК.

### IV. Единая экосистема (All-in-One)

| Модуль | В1 | В2 | В3 |
|--------|----|----|-----|
| POS-терминал (продажи) | демо | **prod** | offline POS |
| Склад / инвентаризация | v0.1 | v0.1 + цех | Event Sourcing, supply chain |
| CRM / лояльность | — | профиль гостя, история, избранное | полноценная loyalty |
| Аналитика / персонал | RBAC | УК-мониторинг, транзакции, журнал | Labour Cost, алерты, HR |

## 4. Технологический манифест

- **Умное приложение, надёжная база:** логика в Ruby on Rails; PostgreSQL + RLS — изоляция данных точек.
- **Гибридный фронтенд:** витрина `/shop` — Svelte + Vite; **киоск — backend API в В2**, UI на Flutter — **В3+**. Панели (УК, manager, barista, prep_kitchen) — Rails + Hotwire.
- **Data-Driven:** действия порождают события для аналитики и аудита (журнал УК, `admin_audit_logs`).

## Веха 2 — «Рост сети» (**в продукте на Fly**, формальная приёмка §I **открыта**, 2026-08)

Расширение с **1 demo-org** до **сети из коробки** + **реальная оплата** на prod-стенде.

### Инфраструктура и УК

| Область | Что есть |
|---------|----------|
| Онбординг | УК → org → точки (SAL/KIT/ENT) + prep_kitchen; карточка входов (URL, модули, staff) |
| URL витрины | Режим A: `{slug}.{SHOP_BASE_DOMAIN}/shop`; на Fly — режим B: `/shop?tenant_id=` |
| УК-мониторинг (2A) | Мониторинг точек, журнал событий, сессии, список транзакций по точке |
| Feature flags | Модули точки — скрытие разделов или «модуль выключен» |
| RBAC | Все роли персон (franchise/shift manager, barista, prep worker) — прогнаны на Fly |

### Витрина `/shop` (поток 1)

| Область | Что есть |
|---------|----------|
| Каталог | Меню из УК = витрина = barista; обязательные модификаторы; цены с cache bust |
| Оплата | **Т-Банк** (`SHOP_SIMULATE_PAYMENT=0`): card/sbp → `pending_payment` → callback → `accepted`; cash — сразу `accepted` |
| Сохранённые карты | Init/Recurrent, 1-click, save_card toggle — **код готов**, финальный апрув заказчика в работе |
| PWA | Установка на домашний экран, долговечные сессии |
| Гость | Профиль (email/phone OTP, SMS.ru), связка Email↔Phone, избранное, личный кабинет |
| UX | Checkout + email verify; режим работы точки; адрес/выбор точки в шапке; bottom sheet корзины; Quick Repeat; виджет статуса (FCM / Wallet) |
| Уведомления | Push FCM v1 — статус заказа на экране гостя |

### Операции и бариста (поток 2)

| Область | Что есть |
|---------|----------|
| Табло B2.1 | 6 карточек, live без F5 (Solid Cable + worker), звук нового заказа — **апрув заказчика** |
| Киоск | `POST /kiosk/api/auth`; заказы через shop API; curl smoke PASS — **Flutter UI → В3** |
| Смена | **Гибрид:** shop/киоск без смены; barista только с `CashShift.open`; CloseWizard — online-платежи за 24ч информативно |
| Надёжность оплаты | Outbox (`TbankCallbackJob`), Circuit Breaker, idempotency callback, stuck payments → Telegram; guard amount mismatch на events callback |

## Веха 3 — «Профессиональный учёт» (в планах)
