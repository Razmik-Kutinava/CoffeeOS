Миссия и концепция
CoffeeOS — это не просто кассовое решение, а цифровая операционная система для ресторанов (Restaurant Operating System). Наша цель — предоставить бизнесу инструмент «цифровой франшизы», который позволяет масштабировать сеть кофеен без потери качества, минимизировать человеческий фактор и обеспечить полную прозрачность операций.

Мы строим систему, которая превращает хаос ручного управления в алгоритмизированный бизнес-процесс.

2. Целевая аудитория (Personas)
Франчайзи — Менеджер офиса (franchise_manager): Управляет группой своих точек. Нуждается в консолидированной аналитике в реальном времени (выручка, Labour Cost, скорость производства, рейтинг качества) для контроля эффективности бизнеса без операционного доступа к кассам.

Управляющий точки (GeneralManager): Полностью отвечает за жизнедеятельность одной конкретной локации. Ему необходимы инструменты долгосрочного планирования и глубокой настройки: управление тремя типами меню и локальными ценами, складской учет и расчет себестоимости, кадры, маркетинг и финансовые срезы.

Менеджер смены (ShiftManager): Руководитель кофейни на линии горизонта «Сегодня». Обеспечивает непрерывность работы в текущую смену: оперативно выводит сотрудников, управляет стоп-листами ингредиентов, авторизует планшеты и табло в зале, решает проблемы с текущими заказами.

Бариста (Operator): Линейный сотрудник на кассовом терминале (POS). Нуждается в максимально быстром, отказоустойчивом интерфейсе, который ведет по шагам заказа в запарах и автоматизирует кассовую дисциплину внутри открытой смены.

Ключевые столпы продукта (Core Pillars)
I. Цифровая франшиза и Стандартизация
Система является носителем стандартов бренда. Все процессы — от рецептуры напитков до регламента инвентаризации — зашиты в логику приложения.

Результат: Идентичное качество продукта в любой точке сети, независимо от опыта персонала.

II. Непрерывность бизнеса (Zero-Downtime) — цель, **Веха 3**
Для QSR-сегмента простой системы равен потере прибыли и репутации. Целевая архитектура — Offline-first.

**Веха 1–2:** все каналы работают **только online** (HTTP). Offline, Drift/Hive и очередь синхронизации — **не В2**, перенесены в **В3**.

III. Анти-фрод и Тотальная прозрачность
Бизнес-логика системы исключает возможность махинаций с чеками и бонусами. Полный Event Sourcing склада и ночная сверка — **Веха 3**.

**Веха 1 (база):** привязка заказов баристы к `CashShift`, запрет POS без открытой смены, отмена с обязательной причиной и записью в `admin_audit_logs`, сверка наличности при закрытии смены (`cash_difference`).

IV. Единая экосистема (All-in-One)
Мы избавляем владельца от «лоскутной» автоматизации. CoffeeOS объединяет в себе:

POS-терминал (продажи);

Инвентаризацию и закупки (Supply Chain);

Систему лояльности и CRM;

Аналитический модуль и управление персоналом.

Технологический манифест (Product Principles)
Умное приложение, надежная база: Вся логика — в коде (Ruby on Rails), БД (PostgreSQL) — гарант целостности и изоляции данных (RLS).

Гибридный фронтенд: Витрина/Shop (app/frontend) на Svelte; **киоск — backend API в В2**, UI на Flutter — **В3+**. Все остальные экраны, внутренний операционный контур и панели: Управляющая компания (platform/УК), владелец франшизы/организации, управляющий точки, менеджер смены, терминал/панель бариста (POS), заготовочный цех / prep‑kitchen и кухня, входы работника цеха и работника смены — только Rails + Hotwire.

Data-Driven: Любое действие в системе порождает событие, пригодное для анализа в реальном времени.

## Веха 1 — «Цифровой прилавок» (реализовано в демо, 2026-05)

Рабочий **online-only** прототип одной кофейной сети (демо: 1 организация, 2 точки, заготовочный цех).

| Область | Что есть в демо |
|---------|-----------------|
| Панели | УК (`/admin`), manager, barista POS, prep_kitchen — Rails + Hotwire; RBAC по ролям |
| Витрина | `/shop` — Svelte + Vite; меню, корзина, модификаторы, **имитация оплаты**, история за сегодня |
| Заказы | Shop API и barista POS; **гибрид смены:** shop без `CashShift`, barista только при открытой смене |
| Склад v0.1 | Списание по техкарте при продаже; допуск отрицательного остатка; prep_kitchen — черновик → подтверждение движения |
| Данные | Postgres RLS (существующие политики); онбординг точки в УК; `demo:seed` |
| Не в В1 | Offline, Flutter/киоск UI, реальная оплата, полный журнал склада, loyalty/pickup как продукт |

## Веха 2 — «Рост сети» (реализовано в коде, приёмка §I открыта, 2026-05)

Расширение с **1 demo-org** до **сети из коробки** + **реальная оплата** на prod-стенде. Ops: `docs/operations/milestones/veha_2/checklists/CHECKLIST.md`.

| Область | Что есть |
|---------|----------|
| Онбординг | УК → org → точки (SAL/KIT/ENT) + prep_kitchen; `TenantOnboarding::{Provision, CatalogBootstrap, UrlBuilder}`; **карточка входов** (URL, модули, staff) |
| URL витрины | Режим A: `{slug}.{SHOP_BASE_DOMAIN}/shop`; на Fly demo — режим B: `/shop?tenant_id=` (`SHOP_URL_MODES.md`) |
| Оплата | **Т-Банк** на prod (`SHOP_SIMULATE_PAYMENT=0`): card/sbp → `pending_payment` → callback → `accepted`; cash — сразу `accepted`. **Не ЮKassa.** |
| Надёжность оплаты | Outbox (`TbankCallbackJob`, Solid Queue), Circuit Breaker в адаптере, idempotency callback (cache/Redis) |
| Киоск | `POST /kiosk/api/auth` (device_token → tenant); заказы через **shop API**; **Flutter UI — не В2** |
| Live-табло | Barista POS: Turbo Streams / Solid Cable — заказ на табло **без F5** (после worker на Fly) |
| Feature flags | Модули точки — скрытие разделов или «модуль выключен» |
| Смена | **Гибрид сохранён:** shop/киоск без смены; barista только с `CashShift.open`. **Единая смена на всех каналах — В3** |
| Не в В2 | Offline POS (IndexedDB), Flutter UI киоска/мобилки, единая смена, refund, Z-отчёт, полный Event Sourcing склада |

**Приёмка:** MCP/автотесты — имитация или signed callback; **живое demo заказчика** — реальные деньги на форме банка (этап 3). §I В2 **не закрыта**. `bin/rails test` — **554/0** (2026-05-30).

Ключевые показатели успеха (KPI)

Мы считаем продукт успешным, если он достигает следующих целей для клиента:

Speed of Service: Сокращение времени обслуживания клиента на 15%.

Waste Reduction: Снижение потерь и списаний ингредиентов на 10-12%.

Fast Onboarding: Обучение нового сотрудника работе с системой занимает не более 20 минут.

Uptime: Доступность критических функций продажи — 99.9%.
