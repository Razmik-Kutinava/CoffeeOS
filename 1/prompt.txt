# TASK_93-H — Блок H: Корзина cookie / overflow

Зонтик: **TASK_93** / `#93` — Critical path hardening.  
Этот SBR-прогон: **только TASK_93-H**.

Title чата: `Задача 93 — Critical path hardening (блок H)`.

---

## 1. Зачем

Корзина shop лежит в **cookie session** (`session[:shop_cart]`). Лимит cookie ~**4KB**. При переполнении:

```ruby
rescue ActionDispatch::CookieOverflow
  clear! + 422
```

Константы **`ActionDispatch::CookieOverflow` в Rails 8 скорее всего нет** → вместо 422 получаем **`NameError` 500** (или необработанный overflow при commit cookie).

Уже есть: compact modifiers (только id), `MAX_CART_ITEMS = 50` (сумма qty), комментарий про CookieOverflow в `CartService`. Нет: реального rescue-класса, byte-budget guard, теста на >4KB path.

## 2. Цель блока

**Большая корзина → понятный 422 + clear (или отказ add до записи), не 500 / NameError.**

## 3. Scope / Non-scope

**В scope (H1–H3):**
- `Shop::Api::CartController` — rescue / error path на add (и update, если тоже пишет session)
- `Shop::CartService` — лимит линий / byte-budget / свой `OverflowError`
- Решение H2: лимиты **и/или** server-side store (ниже)
- Integration-тест переполнения

**Вне scope:** UI CartSheet UX, MobileCart merge при профиле (уже есть таблица — можно использовать в H2, но не обязателен полный PWA redesign), A–G, deploy.

## 4. Продуктовые правила (SPEC до RED)

| Правило | Решение |
|---------|---------|
| **R1** | Запрещён мёртвый `rescue ActionDispatch::CookieOverflow` без проверки `defined?` / реального класса |
| **R2** | Канон ошибки: свой `Shop::CartService::OverflowError` (или `CookieOverflowError`), который контроллер ловит → **422** + clear + русское сообщение |
| **R3** | **Proactive guard** до commit: оценка размера payload / лимит **distinct lines** (рекомендация: max **15–20 линий** или `Marshal`/`JSON` size session cart > порог ~3KB) → `OverflowError` **до** ответа, не ждать Rack |
| **R4** | H2 минимум: R3 + лимиты. **Полный server-side** (`MobileCart` / Rails cache keyed by session_id) — **в том же блоке**, если cookie-only не закрывает DoD на реальном >4KB с модификаторами; иначе зафиксировать «cookie + hard line/byte cap» как достаточный DoD |
| **R5** | `update`/`replace_line!` тоже не должны 500 при раздувании session |
| **R6** | Сообщение клиенту стабильное: `"Корзина переполнена…"` (или короче); UI может показать toast — не блокер |

**Рекомендация SPEC (дешёвый GREEN):**  
H1 = свой OverflowError + rescue; H2 = `MAX_CART_LINES` (distinct) + `MAX_SESSION_CART_BYTES` check в `touch_cart_session!`; H3 = тест.  
Server-side DB — только если после лимитов всё ещё легко упереться в 4KB на типичном меню.

## 6. Не ломать

1. Persist cart across requests (session cookie + api key) — `cart_persistence_test`.  
2. Compact modifiers — только id в session.  
3. `MAX_ITEM_QUANTITY` / суммарный qty cap (или согласовать с новым line cap).  
4. pending order keeps cart until pay success.  
5. clear after successful pay.

## 7. Матрица приёмки H1–H3 ↔ тесты

Блок H закрыт только если **все** T-H* PASS.

### H1 — Реальный rescue

| ID | Тест | Assert |
|----|------|--------|
| **T-H1a** | `CartController rescues CartService::OverflowError with 422 and clears` | stub/force OverflowError на add → status **422**, body error про переполнение, cart empty |
| **T-H1b** | `no NameError from ActionDispatch::CookieOverflow constant` | `refute defined?(ActionDispatch::CookieOverflow) && controller still handles overflow` **или** grep/source test: контроллер **не** рескует несуществующую константу в одиночку |
| **T-H1c** | `update path rescues overflow too` (если applies) | 422 + clear / reject |

### H2 — Лимит / store

| ID | Тест | Assert |
|----|------|--------|
| **T-H2a** | `add! raises OverflowError when distinct lines exceed MAX_CART_LINES` | N+1-я unique line → OverflowError; session не раздута сверх лимита |
| **T-H2b** | `touch_cart_session! / add! raises when estimated bytes exceed budget` | искусственно большой payload (много линий/модов) → OverflowError |
| **T-H2c** | (если server-side) cart survives beyond cookie size | add many lines → GET cart всё ещё полный; cookie не обязан держать весь JSON |

Если выбран только cookie+cap: T-H2c skip в SPEC.

### H3 — >4KB / переполнение → не 500

| ID | Тест | Assert |
|----|------|--------|
| **T-H3a** | `POST /cart/add repeatedly until overflow returns 422 not 500` | цикл add разных products (или stub огромный session) → последний ответ **422** (или промежуточный отказ), **никогда** 500; после 422 GET cart пустой или без нового item |
| **T-H3b** | `normal small cart still 200` | регресс 1–3 позиции |
| **T-H3c** | ручной чеклист REVIEW | 20+ позиций с модификаторами в UI / curl — в отчёте «сделано» |

Файл: `test/integration/shop/api/cart_overflow_test.rb`.

**Как стабильно тестировать без хрупкости:**  
в тесте временно stub `Shop::CartService::MAX_SESSION_CART_BYTES = 200` (или lines=3) → переполнение на 4-й add; отдельно один тест с реалистичным порогом ближе к 4KB если нужно.
