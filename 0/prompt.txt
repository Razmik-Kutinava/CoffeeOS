# Главный экран — повторный заказ (невалидный токен): BottomSheet выбора способа оплаты
Бизнес-цель: Предоставить пользователю возможность изменить или добавить способ оплаты при повторном заказе в случае невалидности токена, предотвращая блокировку флоу.

## Глобальные ограничения
- Запрещено модифицировать глобальный стор авторизации (auth store) и логику refresh-токенов.
- Запрещено импортировать легаси-компоненты кнопок и списков из `legacy/ui`.
- Запрещено хардкодить тексты способов оплаты (использовать только i18n).
- Запрещено изменять архитектуру глобального BottomSheet-менеджера.
- Запрещено создавать новый BottomSheet-компонент — использовать существующий `PaymentMethodBottomSheet` (или аналогичный из дизайн-системы).

## Сценарии и чек-лист (Для todo.md)

- [ ] Шаг 1: Рендер CTA «Добавить карту» вместо «Оплатить» в состоянии peek при невалидном токене
  - Given: Пользователь на Главном экране, контекст повторного заказа, статус токена `invalid`, UI находится в состоянии peek (корзина свёрнута).
  - When: Компонент экрана монтируется / перерисовывается.
  - Then: Кнопка «Оплатить» скрыта. Отображается основная CTA-кнопка с текстом «Добавить карту». При клике на CTA — открывается BottomSheet выбора способа оплаты. При ошибке сети (500/400) до открытия BottomSheet — показывается тост ошибки, BottomSheet не открывается.

- [ ] Шаг 2: Рендер BottomSheet «Способ оплаты»
  - Given: Пользователь нажал CTA «Добавить карту» (или нажал «+ Картой» внутри BottomSheet).
  - When: BottomSheet открывается.
  - Then: Отображается заголовок «Способ оплаты» с кнопкой закрытия (X). В списке:
    - «Картой *1594» — уже привязанная карта (выделена активным состоянием/рамкой).
    - «СБП» — неактивна (disabled, серый фон, тап игнорируется или показывает тост "СБП временно недоступно").
    - «Картой +» — кнопка добавления новой карты.
  - При ошибке загрузки списка способов оплаты (500/400) — внутри BottomSheet отображается inline-заглушка ошибки с кнопкой «Повторить».

- [ ] Шаг 3: Выбор существующей карты в BottomSheet
  - Given: BottomSheet открыт, в списке есть привязанная карта «Картой *1594».
  - When: Пользователь тапает по «Картой *1594».
  - Then: Карта переходит в состояние `selected` (оранжевая рамка/выделение). CTA внутри BottomSheet меняется на «Оплатить» и становится активной. Тап по «СБП» игнорируется.

- [ ] Шаг 4: Добавление новой карты через «+ Картой»
  - Given: BottomSheet открыт.
  - When: Пользователь тапает по «Картой +».
  - Then: Открывается флоу добавления карты (экран/модалка ввода данных карты). После успешного добавления — BottomSheet обновляется (новая карта появляется в списке), CTA «Оплатить» становится активной. При ошибке 400/500 в процессе добавления — ошибка отображается inline внутри экрана добавления карты, BottomSheet не закрывается, данные сохраняются.

- [ ] Шаг 5: Обработка ошибок при оплате (inline в BottomSheet)
  - Given: Пользователь выбрал способ оплаты («Картой *1594» или новую карту), CTA «Оплатить» активна.
  - When: Пользователь нажимает «Оплатить», бэкенд возвращает ошибку 400 (неверные данные карты / недостаточно средств) или 500 (внутренняя ошибка сервера).
  - Then: BottomSheet не закрывается. Ошибка отображается inline внутри BottomSheet (над CTA или в виде баннера) с текстом ошибки. Кнопка «Оплатить» разблокируется (если была в состоянии loading). Выбранный способ оплаты сохраняется. Пользователь может повторить попытку или изменить способ оплаты.

- [ ] Шаг 6: Закрытие BottomSheet
  - Given: BottomSheet открыт.
  - When: Пользователь нажимает кнопку закрытия (X) или свайпает вниз.
  - Then: BottomSheet закрывается. Возврат к peek-состоянию главного экрана. CTA «Добавить карту» остаётся активной (если токен всё ещё невалиден). Стейт выбранного способа оплаты сохраняется в локальном стейте фичи.

## Стратегия тестирования
- Фреймворк: Vitest + React Testing Library (или Jest + RNTL, если React Native).
- Путь к файлам тестов: `src/features/checkout/repeat-order/__tests__/PaymentMethodBottomSheet.test.tsx`
- Критические кейсы:
  - Корректное переключение CTA «Оплатить» ↔ «Добавить карту» в зависимости от флага `isTokenInvalid`.

  - Асинхронное состояние loading кнопки «Оплатить».
  - Inline-рендер ошибок 400/500 внутри BottomSheet без его закрытия.
  - Сохранение стейта выбранного способа оплаты после закрытия/открытия BottomSheet.
  - Маппинг HTTP кодов (400/500) на UI-реакции (inline-ошибки vs тосты).
