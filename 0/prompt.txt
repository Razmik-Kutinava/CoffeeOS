---

### Жёсткие правила

- ErrorCode / rate-limit / insufficient funds банка ≠ сразу баг приложения.  
- Не коммитить PAN/CVV/полные RebillId в артефакты (маска `*5953` ок).  
- Не трогать TbankAdapter «ради красоты»; не новые payment gems.  
- `isTokenInvalid` = **токен карты**, не auth refresh.  
- Min charge ≥10₽.

### Карта slices

| Slice | Цель | Когда |
|-------|------|--------|
| **P** | Preflight: гость + session + (для M2) **есть saved card** | всегда сначала |
| **U** | UserCards E2E: `save_card=true` → MIR в списке → RebillId в БД (сразу или после sync) | после P |
| **O** | One-click happy: Charge по RebillId → заказ accepted | после U |
| **M** | #26 M2: decline/fail one_click → шторка открыта + inline error + карта selected | после P с картой |
| **C** | Code fix | только при FAIL нашего слоя |

Порядок: **P → U → O → M**; C условный.

### Slice P — Preflight (блокер v481)

**DoD:**

### Slice U — UserCards / RebillId E2E (DoD)

```
Given гость на Point A, save_card=true
When оплата новой картой (Init → FA / виджет — канон new_card)
Then payment succeeded / order accepted
And в mobile_payment_methods есть карта (mask, exp, type MIR/…)
And card_token (RebillId) заполнен:
   - либо сразу из FA/webhook
   - либо после sync_for_rebill! / finalize (доказать GetState/retry, не «карта навсегда без токена»)
And GET user/cards отдаёт эту карту этой сессии
```

**Матрица FAIL → Slice C:**

| Симптом | Слой |
|---------|------|
| FA OK, карты нет, webhook был с RebillId | `SavedCardStore` / `allowed_for?` / save_card flag |
| Webhook без RebillId, sync не добрал | `sync_for_rebill!` retries / worker / finalize |
| Карта в БД, GET cards пусто | session / customer_id / merge |
| save_card=false, карта появилась | bug consent |
| Дубль pan+exp | upsert SavedCardStore |

**Delayed RebillId:** если токен появляется в окне sync (логи/повтор GET cards) → **PASS с пометкой delayed**; если через N минут/finalize всё ещё null → **FAIL** нашего sync.
