# TASK_93-F — Блок F: Callbacks / stuck payments / Events

Зонтик: **TASK_93** / `#93` — Critical path hardening.  
Этот SBR-прогон: **только TASK_93-F**.

Title чата: `Задача 93 — Critical path hardening (блок F)`.

---

## 1. Зачем

Внутренние Events и банковский контур «молчат» или залипают:

| Проблема | Код сейчас |
|----------|------------|
| Secrets пустые | `reject_unconfigured_callbacks!` только при `Rails.env.production?`; `authenticate_*` делают `return if blank` → на staging/FLY-like без secrets endpoint открыт |
| Idempotency | claim пишется `state: processing` на 24h; `audit_event` обновляет cache только на `processed`/`failed` — **не** на `rejected` → после 422 (amount mismatch и т.п.) повтор даёт `duplicate: true, ok: true` |
| Stuck payments | `StuckPaymentsCheckJob` только `TelegramAlertJob`, **без** GetState / `TbankPaymentSync` |
| Fiscal | `TbankFiscalNotificationHandler` при skip логирует warn и `{ ok: true, skipped: … }` — без Sentry/retry |

T‑Bank webhook (`Callbacks::TbankController`) в этот блок **не ломаем** (подпись уже есть); F4 — fiscal RECEIPT path.

## 2. Цель блока

**Callbacks не залипают и не молчат:** Events без секретов закрыты на публичном стенде; rejected не держит `processing` 24h; stuck tbank payments дожимаются через GetState; fiscal soft-skip → явный алерт/retry.

## 3. Scope / Non-scope

**В scope (F1–F5):**
- `Callbacks::EventsController` — fail-closed secrets, idempotency claim lifecycle
- `Payments::StuckPaymentsCheckJob` — GetState + sync/дожим
- `Payments::TbankFiscalNotificationHandler` — alert/retry на skip
- Тесты auth Events + claim + stuck + fiscal

**Вне scope:** склад/PaymentStatusUpdater (A), checkout identity (B), SMS `/o/` (C), history per_page (D), Init race (E), RLS (G), Rack store Redis (I — можно оставить MemoryStore, но claim release обязателен), deploy (L).

## 4. Продуктовые правила (зафиксировать в SPEC до RED)

| Правило | Решение |
|---------|---------|
| **R1** | Fail-closed Events, если нет пары `CALLBACK_SHARED_TOKEN` + `CALLBACK_SHARED_SECRET`, когда среда «публичная»: `Rails.env.production?` **или** `ENV["FLY_APP_NAME"].present?` **или** `ENV["CALLBACK_FAIL_CLOSED"]=1`. Dev/test без флага — можно открыто для локальных тестов **или** тесты сами ставят secrets |
| **R2** | После claim `processing`: любой terminal outcome (`processed` / `failed` / **`rejected`**) обновляет или **удаляет** cache key; rejected/422 **не** оставляют `processing` на 24h |
| **R3** | Повтор с тем же key после **успеха** → `duplicate: true, ok: true`; после **reject** → можно ретраить обработку (нет ложного ok) или явный `duplicate` со `state: rejected` **без** повторного мутирования — зафиксировать одно в SPEC (рекомендация: **release claim on reject**, retry allowed) |
| **R4** | `StuckPaymentsCheckJob`: для каждого stuck tbank payment с `provider_payment_id` → `TbankPaymentSync` / GetState → обновить статус; без id → alert only; ошибки sync → log + alert, job не падает целиком |
| **R5** | Fiscal skip (`payment_not_found` / `missing_fiscal_ids`) → `Rails.error.report` (или `AdminAuditLog` + Telegram); опционально enqueue retry job 1–2 раза; **не** маскировать как тихий success без сигнала |
| **R6** | Amount mismatch на Events по-прежнему **422** и не меняет payment на succeeded |
