## Задание агенту (SBR): Apple Wallet PassKit signing — prod `.pkpass`

### Контекст

Сейчас `Shop::AppleWallet::PassBuilder`:
- `WALLET_SIMULATE=1` / нет certs → stub `PKPASS_STUB:…` (`simulated: true`);
- certs в ENV есть → **падает** `GenerationError: WALLET signer configured but PassKit signing not implemented yet`.

Скачивание: `GET /shop/api/orders/:id/wallet_pass` → `PassUpdater` → `send_data` `application/vnd.apple.pkpass`.

Runbook: `docs/operations/milestones/veha_2/runbooks/APPLE_WALLET_ORDER_PASS.md`  
ТЗ-корни: #38 / #35 B3 · `customer_tasks/Фоновые уведомления прогресс-бар Android FCM и Apple Wallet iOS.md`

### Цель (DoD этого SBR)

Когда `Config.certs_configured?` и **не** `simulate?`:
1. `PassBuilder.build!` возвращает **реальные байты ZIP `.pkpass`** (не stub-строку).
2. В ZIP минимум: `pass.json`, `manifest.json`, `signature` (PKCS#7 detached), обязательные иконки/картинки pass.
3. `pass.json` содержит face/back/strip семантику как сейчас (status / QR на `ready`, chat/tips deep links, strip progress).
4. Simulate / test без certs — **без регрессии** (текущие `pass_builder_test` остаются зелёными).
5. Без certs / `WALLET_FORCE_UNAVAILABLE` — поведение как сейчас.

### Scope IN

- `Shop::AppleWallet::PassBuilder` — ветка prod signing вместо `raise … not implemented`.
- Новый узкий сервис/модуль подписи (например `PassSigner` / `PkpassArchive`) в `app/services/shop/apple_wallet/` — не раздувать `PassBuilder`.
- ENV: уже есть `WALLET_PASS_TYPE_ID`, `WALLET_TEAM_ID`, `WALLET_SIGNER_CERT_PEM`, `WALLET_SIGNER_KEY_PEM`. При необходимости добавить **`WALLET_WWDR_CERT_PEM`** (Apple WWDR intermediate) — документировать в runbook + `Config.certs_configured?`.
- Тесты Minitest: зеркало `test/services/shop/apple_wallet/`.
- Обновить runbook: убрать «signing TBD» для PKCS7; описать ENV и smoke.

### Scope OUT (не трогать в этом SBR)

- **APNs Wallet push + device tokens** (`ApnsClient` сейчас тоже stub) — **отдельный SBR** (нужен Wallet web service register device).
- Wallet web service (`/v1/devices/...` Apple pass update endpoints) — OUT.
- Barista status / FCM / SMS cascade / payment — **не ломать**.
- Новые gem’ы оплаты / Stripe — запрещено. Если нужен gem для PKCS7/ZIP — **спросить владельца**; предпочтительно OpenSSL + stdlib `Zip` (как принято в Rails), без лишних зависимостей.
- RSpec / Vitest — запрещено (только Minitest / `.mjs` если фронт).

### Канон / ограничения CoffeeOS

- SBR: SPEC → RED → GREEN → REVIEW (`spec-build-review.mdc`).
- Сервисы в `app/services/shop/…`; ownership `wallet_pass` не ломать.
- Tenant/RLS: pass уже через `OrderWalletPass` + order ownership — не обходить RLS.
- Секреты: PEM только из ENV / Fly secrets — **не коммитить** ключи/certs в репо; в тестах — inline fake PEM или fixture в `test/fixtures/files/wallet/` (тестовые самоподписанные, не prod).
- Hot-path: в `todo.md` обязательны **Не ломать** + **Проверка**.

### Acceptance (тесты RED→GREEN)

1. **Simulate (как сейчас):** `WALLET_SIMULATE=1` → `built[:simulated] == true`, face/back/strip без изменений.
2. **Prod signing (новый):** stub ENV certs + WWDR → `build!` → `bytes` — бинарный ZIP; внутри есть `pass.json`, `manifest.json`, `signature`; `simulated` отсутствует или false.
3. **pass.json:** `passTypeIdentifier` / `teamIdentifier` / `serialNumber` / `authenticationToken` / `storeCard` (или eventTicket — зафиксируй один тип в SPEC) / релевантные fields по статусу; на `ready` — barcode/QR с order number.
4. **Невалидный PEM** → `GenerationError` (не 500 без класса).
5. **Регрессия:**  
   `ruby bin/rails test test/services/shop/apple_wallet/ test/jobs/shop/ready_push_job_test.rb`  
   (+ точечный integration `wallet_pass` если есть).

### Не ломать

1. `WALLET_SIMULATE=1` / test без certs — stub path.
2. `ReadyPushJob`: Unavailable → FCM fallback; GenerationError → retry.
3. `GET …/wallet_pass` ownership / 404 чужого заказа.
4. FCM `firebase-messaging-sw.js` и каскад SMS.

### Порядок работы агента

1. **PHASE 1 SPEC** — `todo.md` (файлы, Не ломать, Проверка), шапка SESSION/HANDOFF; зафиксируй формат pass (`storeCard` vs `eventTicket`), список файлов внутри `.pkpass`, нужно ли `WALLET_WWDR_CERT_PEM`.
2. **RED** — падающие тесты на prod bytes / ZIP / pass.json; коммит `test: … [RED]`; стоп если нет «ебашь до конца».
3. **GREEN** — реализация signing; регрессия зоны; коммит `feat: … [GREEN]`.
4. **REVIEW** — bugbot + security-review + Entire + push CI. Deploy — только по апруву владельца.

### Критерий «готово»

- Certs configured → `.pkpass` валидной структуры (локально: unzip + наличие signature; на iOS device — отдельный ручной smoke вне CI, если есть Apple Pass Type ID).
- Без certs / simulate — как до задачи.
- APNs real push — **не** входит; в отчёте явно: «slice PKCS7 done · APNs device register — следующий SBR».
