### Решение заказчика (Gherkin / Acceptance) — что закрыть

Из ТЗ #71 (CRM-связка + Subtask 9 / bounce / idempotency):

1. **Consent gate:** `marketing_consent=false` → CRM job **не** enqueue (уже в модели); повторно не синкать.  
2. **Enqueue:** `marketing_consent=true` → `SyncContactToCrmJob.perform_later`.  
3. **Identity:** в CRM уходит минимум `email`, `user_id`/`customer_id`, `order_id`, флаг opt-in; телефон — если есть у customer.  
4. **Реальный HTTP** в CRM API (не log-only).  
5. **Ошибки CRM:** не блокируют `EmailService` / оплату; job retry по Solid Queue; лог ошибки.  
6. **Bounce:** `OrderEmail.status=bounced` → job no-op; контакт не в рассылках (opt-out / exclude list — по возможностям провайдера).  
7. **Idempotency:** повтор job / повторный webhook не плодит дубли контактов (upsert по email).  
8. **Security:** ключи только ENV; фронт credentials не видит.

### Этот проход: **Slice A — живой CRM sync**

#### Цель (DoD)

1. При `marketing_consent=true` и `status != bounced` job вызывает CRM API и создаёт/обновляет контакт.  
2. При `consent=false` job не ставится (регресс модели).  
3. При `bounced` mid-flight job выходит без вызова API.  
4. Повторный `perform` того же `order_email_id` — upsert, не дубль.  
5. CRM down → исключение → retry job; email в БД уже сохранён.  
6. Без API key в non-test → явная ошибка/skip с логом (как Brevo email: не silent success в prod без политики — зафиксируй в SPEC: `raise` для retry **или** log+return; предпочтительно raise → Solid Queue retry).  
7. Minitest зелёные; RSpec-заготовки **не** использовать как гейт (переписать в `test/jobs/sync_contact_to_crm_job_test.rb`).

#### Scope IN
