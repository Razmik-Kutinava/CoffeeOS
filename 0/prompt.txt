# TASK_93-I — Блок I: OTP / rate limit / auth abuse

Зонтик: **TASK_93** / `#93` — Critical path hardening.  
Этот SBR-прогон: **только TASK_93-I**.

Title чата: `Задача 93 — Critical path hardening (блок I)`.

---

## 1. Зачем

На Fly несколько web-машин. Сейчас:

```ruby
Rack::Attack.cache.store = ActiveSupport::Cache::MemoryStore.new
```

Лимиты **per-process** → brute OTP / flood `/o/` можно размазать по инстансам.

Отправка SMS/Callcheck throttled; **`POST .../phone_otp/verify_sms` — нет**.  
Код SMS: **`%04d`** (10 000 вариантов); `verify_sms!` уже принимает 4–6 цифр.

**I4 / short-link:** правило `shop/order_short_link/ip` в `rack_attack.rb` **уже есть** (лимит 30/min) с пометкой «shared store → TASK_93-I». **Не дублировать** в C; в I — сделать store общим, чтобы C4 заработал на multi-machine.

Solid Cache **не** подходит для Rack::Attack (`increment` нет) — нужен **Redis** (или иной store с atomic increment).

## 2. Цель блока

**Лимиты общие на весь Fly; verify SMS не открыт для brute; OTP достаточной длины (если продукт ок); short-link throttle живой через shared store.**

## 3. Scope / Non-scope

**В scope (I1–I4):**
- Shared Rack::Attack cache store (Redis)
- Throttle `verify_sms` (+ legacy `phone_otp/verify`, email verify — по SPEC)
- OTP length 4→6 (SMS phone), UI/копирайт
- I4: **не** второе правило `/o/` — только verify что правило есть + работает на shared store

**Вне scope:** смена Callcheck провайдера, SMS.ru API, блок C текст SMS, MemoryStore→Redis для всего Rails.cache приложения (можно оставить SolidCache для app cache; Attack — отдельно), deploy Redis на Fly (**L** или ops в этом блоке как runbook).

## 4. Продуктовые правила (SPEC до RED)

| Правило | Решение |
|---------|---------|
| **R1** | Production/FLY: `Rack::Attack.cache.store` = **Redis** (`REDIS_URL` / `RACK_ATTACK_REDIS_URL`). Dev без Redis → MemoryStore + warn log. Test → MemoryStore / disable как сейчас |
| **R2** | Не использовать SolidCache для Attack increment |
| **R3** | Throttle verify: `POST /shop/api/phone_otp/verify_sms` (+ `/phone_otp/verify` legacy) — по **IP** и по **phone** (из body), лимит например **5 / 1.minute** (или 10) — зафиксировать цифры в SPEC |
| **R4** | Email `email_otp/verify` — тот же класс защиты (рекомендуется в том же блоке) |
| **R5 / I3** | SMS OTP length = **6** (`%06d`, 1e6). UI: 6 полей/маска. Callcheck **не** менять. Product reject 6 → явно skip I3 в SPEC до RED, не после |
| **R6 / I4** | Одно правило `shop/order_short_link/ip`; I только shared store + регресс-тест что throttle срабатывает |
| **R7** | `MobileOtpCode` MAX_ATTEMPTS остаётся defense-in-depth; Attack — первая линия |

## 6. Не ломать

1. Callcheck init/poll throttles (20s / 60s SMS send).  
2. `Retry-After` JSON для phone OTP.  
3. `Rack::Attack.enabled = false` в test по умолчанию; тесты Attack **включают** локально + `cache.clear`.  
4. verify принимает код после смены длины (старые 4-digit в полёте — TTL короткий; ок invalidate).  
5. Short-link HMAC / bind (C) — не трогать логику, только store.

## 7. Матрица приёмки I1–I4 ↔ тесты

Блок I закрыт только если **все** T-I* PASS (с учётом skip I3 по SPEC).

### I1 — Shared store

| ID | Тест | Assert |
|----|------|--------|
| **T-I1a** | `Rack::Attack store is not MemoryStore in production config` | stub `Rails.env.production?` / `FLY_APP_NAME` + `REDIS_URL` → store class Redis* / RedisCacheStore |
| **T-I1b** | `increment is shared` | два «логических» процесса / два write через один Redis (в CI: redis service или fakeredis) → второй hit видит counter первого |
| **T-I1c** | без REDIS_URL в production → явный boot error **или** documented fail-open с ERROR log (выбрать в SPEC; рекомендация: **fail boot** на FLY) |

### I2 — Throttle verify_sms

| ID | Тест | Assert |
|----|------|--------|
| **T-I2a** | `verify_sms exceeds limit → 429` | enable Attack; N+1 POST verify_sms → 429 + RATE_LIMIT_EXCEEDED |
| **T-I2b** | under limit → не 429 (может 422 неверный код) | |
| **T-I2c** | throttle by phone key | разные IP, один phone → всё равно лимит (если R3 phone key) |
| **T-I2d** | legacy `/phone_otp/verify` covered | 429 аналогично |

### I3 — OTP 6 digits (если в SCOPE)

| ID | Тест | Assert |
|----|------|--------|
| **T-I3a** | `send_sms_code! generates 6 digit code` | code =~ /\A\d{6}\z/ |
| **T-I3b** | verify accepts 6 digit | happy path |
| **T-I3c** | frontend expects 6 (source assert) | Checkout/phone UI length=6 / pattern |

Если I3 skip: в REVIEW «I3 DEFER» + не блокирует DoD I.

### I4 — Short-link (без дубля)

| ID | Тест | Assert |
|----|------|--------|

| **T-I4b** | many GET `/o/...` → 429 | как C4; на shared store (если redis в test) |
| **T-I4c** | **нет** второго duplicate throttle path для `/o/` | grep один matched name |
