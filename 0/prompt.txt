# TASK_93-C — Блок C: SMS «заказ готов» + short link

Зонтик: **TASK_93** / `#93` — Critical path hardening.  
Этот SBR-прогон: **только TASK_93-C**.

Title чата: `Задача 93 — Critical path hardening (блок C)`.

---

## 1. Зачем

SMS текст хардкодит **`codeblack.xyz/o/{hash}`**, а production `config.hosts` пускает только `*.fly.dev`. Итог: ссылка из SMS либо не на наше приложение, либо HostAuthorization режет запрос. Route `/o/:hash` и HMAC уже есть; bind session есть; **throttle на `/o/` нет**; TTL нет.

Сейчас:
- `OrderReadySmsLink::PREFIX` → `codeblack.xyz`
- `GET /o/:order_hash` → bind + redirect `/shop?...#/order/:id`
- Тесты: roundtrip hash, 404, redirect+bind
- `rack_attack`: throttle на `/o/` **отсутствует**

## 2. Цель блока

**SMS → клиент открывает статус заказа на живом хосте приложения; сессия биндится; HostAuthorization не режет; brute MAC ограничен.**

## 3. Scope / Non-scope

**В scope (C1–C5):**
- Текст/URL SMS (`PREFIX` / base host из env)
- `config.hosts` + `host_authorization` под выбранный SMS-домен **или** отказ от стороннего домена в тексте
- Регрессия `/o/:hash` + reconnect bind
- Rack::Attack throttle на `GET /o/*`
- C5: TTL и/или одноразовость токена (**в этом блоке целиком** — см. §4)

**Вне scope:** Callcheck/SMS OTP auth (B/I), содержимое статуса заказа UI, FCM, склад (A), deploy (L).  
Смена MemoryStore→Redis для Attack — блок **I**; в C достаточно throttle-правила (даже на MemoryStore), с пометкой «shared store в 93-I».

## 4. Продуктовые правила (зафиксировать в SPEC до RED)

| Правило | Решение |
|---------|---------|
| **R1** | Канон хоста SMS: **`ENV["SHOP_SMS_LINK_HOST"]` или `ENV["APP_HOST"]`**, fallback `coffeeos.fly.dev`. **Не** хардкод мёртвого домена без DNS |
| **R2** | Два допустимых режима (выбрать **один** в SPEC): **(A)** текст = `{host}/o/{hash}` где host ∈ fly/APP_HOST; **(B)** брендовый `codeblack.xyz` **только если** DNS → приложение **и** host добавлен в `config.hosts` |
| **R3** | Длина SMS с префиксом: сохранить бюджет **≤70** символов (или явно поднять лимит в тесте+доке, если host длиннее — тогда укоротить префикс) |
| **R4** | `/o/:hash`: valid → 302 + bind guest + `reconnect_token`; invalid → 404 |
| **R5** | Throttle: лимит на IP (и опционально на hash) для `GET /^\/o\//` — порядок как у `tv_board` (достаточно жёстко против 2³² brute) |
| **R6 / C5 в блоке** | **Включить в DoD:** токен с **TTL** (например 48h / 7d с момента ready/SMS) **или** one-time consume после первого успешного `/o/`. Без «опционально потом» — иначе блок C неполный |

**Рекомендация канона:** режим **R2-A** (`coffeeos.fly.dev` / `APP_HOST`) — меньше DNS/certs; бренд в тексте можно оставить словами «CODE:BLACK», URL — наш host.

## 6. Не ломать

1. HMAC + `secure_compare`; unsigned UUID-only → nil/404.  
2. Только `source: :mobile` заказы.  
3. Redirect только на relative `/shop?...` (`allow_other_host: false`).  
4. Бюджет длины SMS (R3).  
5. Guest reconnect / status sheet после bind (#82 path).

## 7. Матрица приёмки C1–C5 ↔ тесты

Блок C закрыт только если **все** T-C* PASS.

### C1 — PREFIX / URL из канона хоста

| ID | Тест | Assert |
|----|------|--------|
| **T-C1a** | `sms_message_for uses configured host not hardcoded dead domain` | stub/set `APP_HOST` или `SHOP_SMS_LINK_HOST` → сообщение содержит `{host}/o/{hash}`; **нет** `codeblack.xyz` **если** выбран режим R2-A |
| **T-C1b** | `sms_message length within budget` | `sms_message_for(order).length <= 70` (или новый лимит из SPEC) |
| **T-C1c** | fallback host | без env → безопасный default (`coffeeos.fly.dev`), не произвольный чужой домен |

Файл: `order_ready_sms_link_test.rb` (переписать assert с хардкодом `codeblack.xyz`).

### C2 — hosts / HostAuthorization

| ID | Тест | Assert |
|----|------|--------|
| **T-C2a** | production hosts include SMS host **if** R2-B | если бренд-домен в тексте — он в `Rails.application.config.hosts` (тест на конфиг или integration с `Host` header) |
| **T-C2b** | R2-A: SMS URL host is already allowed | host из сообщения ∈ fly pattern / APP_HOST; отдельный брендовый host не обязателен |
| **T-C2c** | `/o/` not blocked for allowed host | integration: `get "/o/#{hash}", headers: { "HOST" => allowed }` → redirect, не 403 host |

(В test env hosts часто свободные — для T-C2a допустим unit на список hosts в `production.rb` через чтение конфига / отдельный assert-файл.)

### C3 — Route + reconnect bind (регресс + усиление)

| ID | Тест | Assert |
|----|------|--------|
| **T-C3a** | existing: valid hash → redirect + `#/order/:id` + reconnect_token | как сейчас + tenant_id |
| **T-C3b** | bind guest session | `CustomerSession.customer_id` / reconnect bind после GET |
| **T-C3c** | unknown / bad MAC → 404 | без bind |
| **T-C3d** | forged MAC (wrong last bytes) → 404 | |

Файл: `order_short_links_test.rb`.

### C4 — Throttle GET `/o/:hash`

| ID | Тест | Assert |
|----|------|--------|
| **T-C4a** | many GETs `/o/...` from same IP → 429 | после N запросов (лимит из rack_attack) `assert_response :too_many_requests` |
| **T-C4b** | under limit still 302/404 | не ломает нормальный один клик |

Файл: новый integration + правило в `rack_attack.rb`, например:

```ruby
throttle("shop/order_short_link/ip", limit: 30, period: 1.minute) do |req|
  req.ip if req.get? && req.path.start_with?("/o/")
end
```

(цифры зафиксировать в SPEC; в тесте — тот же limit или `Rack::Attack.cache.store.clear` + временный override).

### C5 — TTL / одноразовость (в DoD блока)

| ID | Тест | Assert |
|----|------|--------|
| **T-C5a** | expired token → 404 | hash валидный по MAC, но order ready/SMS older than TTL **или** embedded expiry → not_found; session **не** bind |
| **T-C5b** | one-time: second GET after success → 404 **или** redirect without re-bind (выбрать одно в SPEC) | если one-time |
| **T-C5c** | within TTL first open → 302 + bind | happy path |

Если выберете **только TTL** без one-time — T-C5b skip с пометкой в SPEC; **хотя бы TTL обязателен**.  
Реализация: хранить `sms_link_expires_at` / использовать `order.updated_at`+READY / Redis consume key — решение в GREEN, тесты красные на RED.
